# Advisor Topic Search — Round 06 (2026-08-23)

## Objective: brutally reduce the current top ten

This round deliberately stops rewarding a topic for merely being interesting, recent, or mechanistically analyzable.

New venue policy for this audit:

- primary seed venues: **ACL first**, then EMNLP / NAACL;
- also acceptable when strongly relevant: NeurIPS / ICML / AAAI / IJCAI;
- primary seed must come from the CCF A/B AI/NLP conference pool;
- **EACL is not eligible as a primary seed** for promotion;
- a method such as probing / activation patching / steering is never novelty by itself.

The decisive question is now:

> **If we start coding tomorrow, which topic has the highest chance of producing a clean, publishable scientific result without first surviving a chain of hidden assumptions?**

A candidate is removed from the active pool if any of the following holds:

1. the scientific object is already crowded by near-identical papers;
2. the causal contrast changes several things at once;
3. mechanism analysis requires cross-model/checkpoint alignment or broad hyperparameter fishing before the claim is identifiable;
4. the natural next step is merely “apply probe / patch / steering to an existing benchmark”;
5. the prerequisite phenomenon is not already present in the exact open model / artifact regime we can run;
6. a null result would leave little scientific conclusion.

# 1. KEEP — SemTrace: where does semantic execution break when lexical retrieval survives?

Seed:

> ACL 2026 main, *Sense and Sensitivity: Examining the Influence of Semantic Recall on Long Context Code Understanding*.

Why it survives the brutal audit:

- seed phenomenon is large, not marginal: semantic recall can collapse near the middle while lexical retrieval remains strong;
- official reproduction package is public;
- open models are already part of the seed evaluation;
- SemTrace is synthetic and executable;
- program intermediate states can be generated exactly;
- position provides a natural same-model counterfactual;
- no annotation or paid API is needed for our primary open-model experiment.

### Collision that narrows the novelty

Generic claims are already crowded:

- long-context models can internally retain information that generation fails to expose;
- lost-in-the-middle has known hidden-state / attention correlates;
- transformer state tracking has already been mechanistically studied;
- finite-state computation circuits have already been localized in other controlled tasks.

Therefore the project must **not** be framed as:

> “Do LLMs internally know information that they fail to output?”

or

> “How do transformers track state?”

The surviving question is narrower and stronger:

> **Why does context position selectively destroy operational state transition when lexical access to the same code remains available?**

### Frozen prerequisite shape

Use the same program and same model:

```text
edge position  -> semantic execution correct
middle position -> semantic execution wrong
```

Then require lexical retrieval to remain correct in both.

Only this `edge-correct / middle-wrong / lexical-intact` cell is eligible for mechanism analysis.

### Best first mechanism question

For a sequential SemTrace program with exact intermediate states, determine whether middle placement causes:

1. failure to encode the relevant operation;
2. failure to update the intermediate program state;
3. correct intermediate state followed by failed propagation/readout.

This is a bounded mechanism search because every program step has an exact expected state.

### Kill line

Kill or heavily narrow if:

- the critical cell is sparse in the chosen open model;
- lexical retrieval also collapses on the same items;
- intermediate-state decoding is equally poor at edge and middle, leaving no selective computation story;
- the result reduces to a generic position channel already explained by prior lost-in-the-middle work.

**Status: SURVIVAL_TOP / CODE_NEXT.**

# 2. KEEP — MedEinst: encoding failure or failed belief update under Einstellung?

Seed:

> ACL 2026 main, *MedEinst: Benchmarking the Einstellung Effect in Medical LLMs through Counterfactual Differential Diagnosis*.

Why it survives:

- classic Einstellung / mental-set problem is independently meaningful;
- 5,383 control–trap pairs already exist;
- the primary critical cell is already defined by the seed: control correct, trap reverts to the control diagnosis;
- labels are exact at the diagnosis level;
- open models already show substantial Bias Trap Rate;
- no new annotation is needed to establish the behavioral failure.

The surviving scientific question is:

> **When decisive counterevidence is introduced, does the model fail to encode it, or is it encoded but unable to update the already-formed diagnostic state?**

This is much better than simply classifying errors into “blindness / underthinking / overthinking,” which the seed already does at the text-trace level.

### Mandatory gate before any hidden-state code

We must first run the existing pair-locality audit.

If control→trap edits are truly localized around discriminative evidence, token-/span-level causal intervention is natural.

If edits are diffuse across the narrative, the mechanism claim becomes confounded by broad prompt changes and the project should be downgraded.

### Kill line

Kill if:

- the paired edit is too diffuse;
- open models with adequate control accuracy produce too few Bias Trap events;
- the decisive evidence is simply not represented anywhere on trap failures;
- rescuing the claim requires manually deciding which clinical tokens are “the true evidence” for many examples.

**Status: SURVIVAL_TOP / RUN PAIR-LOCALITY G0.**

# 3. HOLD — In-context representation deployment bottleneck

Seed:

> ACL 2026 main, *Language Models Struggle to Use Representations Learned In-Context*.

Scientifically this may be the strongest object in the pool.

The seed directly reports a dissociation:

```text
novel in-context semantics are encoded in latent representations
BUT
models struggle to deploy them downstream
```

The paper itself leaves mechanism and intervention open, and the Prefilled vs Instruction conditions potentially provide a useful same-model contrast.

### Why it is NOT promoted to immediate implementation

Under our feasibility-first standard, the missing official artifact is not a small inconvenience.

Current search has not recovered an official repository / released generator / exact reproduction code.

Reconstructing Adaptive World Modeling ourselves would reintroduce several risks:

- prompt implementation mismatch;
- task-generation mismatch;
- reproducing the latent-representation measurement;
- accidentally choosing an easier/harder regime than the paper;
- spending days before verifying the exact critical cell.

Also, generic “backpatch the representation to earlier layers” is not novel: neighboring work has already used back-patching / contextualization interventions.

The real question would have to be:

> **What deployment-specific routing/readout computation makes an already learned in-context representation inert under one interface but usable under another?**

### Promotion gate

Only promote when at least one of these becomes true:

1. official code/data are located or released;
2. the paper appendix permits an exact, small reconstruction that reproduces the published critical cell on one open model without tuning.

**Status: SCIENCE_TOP / HOLD_FOR_ARTIFACT.**

# 4. WATCH — Temporal Forgetting

Seed:

> ACL 2026 main, *Temporal Sampling for Forgotten Reasoning in LLMs*.

The behavioral phenomenon is excellent and artifacts are excellent: released Qwen2.5-7B RL checkpoints and sampled outputs already exist.

However, the tempting follow-up — storage loss vs access loss — is experimentally less clean than it sounds.

Why:

- the same math problem can be solved through different long CoT paths at different checkpoints;
- hidden states from different checkpoints are not automatically in the same representational coordinate system;
- cross-checkpoint activation patching adds alignment assumptions;
- prompt-state probes may not capture a reasoning capability that only materializes during generation;
- “recover with a tiny adapter / prompting” overlaps a growing latent-capability elicitation literature.

This can still become a strong project, but it violates our current preference for a decisive first mechanism experiment.

**Status: WATCH, not active.**

# 5. KILL — Decision boundary / self-generated counterfactual explanations

The object is too crowded.

EMNLP 2025 main alone contains at least two highly overlapping papers:

- *LLMs Don't Know Their Own Decision Boundaries: The Unreliability of Self-Generated Counterfactual Explanations*;
- *Can LLMs Explain Themselves Counterfactually?*

Both independently establish that self-generated counterfactual explanations are unreliable / inconsistent with model behavior.

Adding hidden-state probing now looks like method extension rather than a fresh scientific problem.

**Verdict: KILL.**

# 6. KILL / WATCH — MathIF reasoning models lose instruction control

The behavioral result is real and the code/data are excellent.

But a mechanism project quickly becomes:

> “track instruction information through long CoT and steer it.”

This is too close to existing trajectory-representation and inference-steering work on reasoning models unless a new computation-level hypothesis appears.

The current gap is not enough to justify another mechanism paper.

**Verdict: remove from active pool.**

# 7. KILL — IFEval++

Excellent engineering, weak next scientific question.

The seed establishes nuanced paraphrase robustness failures very thoroughly. The obvious next step — probing why semantically equivalent instructions produce different behavior — is an analysis method applied to a robustness benchmark, not a sufficiently new question.

**Verdict: KILL.**

# 8. KILL — instruction tuning increases misinformation susceptibility

The result is interesting, but the clean mechanism claim is difficult:

```text
base model vs instruct model
```

changes many things simultaneously.

Without the exact post-training trajectory, attributing the shift to a specific conflict-routing mechanism is weak. The surrounding knowledge-conflict / sycophancy literature is also crowded.

This violates the clean-identification gate.

**Verdict: KILL.**

# 9. KILL — RFC-Bench reference-free counterfactual misinformation detection

The comparison-vs-reference-free gap is behaviorally useful, but poor as a mechanism identification contrast:

```text
comparison condition = model receives the original/reference article
reference-free condition = model does not
```

The conditions differ in information, not just access/readout.

If reference-free detection fails, we cannot cleanly infer that an anomaly was internally represented but not acted upon.

A mechanism story would require constructing a new matched diagnostic, defeating feasibility-first.

**Verdict: KILL.**

---

# 10. WATCH — Description–History gap

This is a very good old scientific problem and the ACL 2026 paper provides open-model data.

But the proposed mechanism story has two problems:

1. comparing conversational vs math-reasoning models confounds the entire post-training recipe;
2. the most obvious hypothesis — reasoning models explicitly recover probabilities / expected values from histories — is plausible enough that a positive probe alone would not be exciting.

A stronger project would need a causal within-model manipulation showing that a specific internal conversion from sampled outcomes to an explicit probability representation mediates the gap.

That is possible, but it is not yet a simple first shot.

**Status: WATCH, not active.**
