# Candidate 1 — When Is No Evidence Evidence?

## Mother question

**When should a missing observation count as evidence against a hypothesis, and do language models use the expected detectability of evidence when making that judgment?**

## External construct

An absence is informative only relative to an observation model: if evidence would almost certainly have been detected under hypothesis H, failing to observe it is strong negative evidence; if detection was unlikely, the same absence is weak evidence.

This is a classical problem in Bayesian reasoning, cognitive science, forensics, diagnosis, search, and scientific inference. Hsu et al. showed that human judgments about absent events track how surprising / diagnostic the absence is under a Bayesian account.

## ACL / EMNLP / NAACL scope verdict

`MAIN_SCALE`

It is **too narrow** if the whole paper is only one synthetic curve `P(detect|H) -> confidence`.

It becomes Main-scale through one coherent construct with four complementary tests:

1. **Detectability calibration:** same null observation, controlled expected detectability;
2. **Factor decomposition:** separate detectability from raw search effort, coverage wording, false-negative rate, and prior probability;
3. **Evidence accumulation:** multiple failed searches with independent vs overlapping coverage;
4. **Agent boundary:** search / research agents must decide continue-search vs abstain vs conclude absence.

These are not four unrelated benchmarks; they are four manipulations of the same observation-model construct.

## Unique novelty package

### Novelty type

- old question, new answer;
- factor decomposition;
- system diagnosis + principled method.

### Novelty one-liner

> **Existing LLM abstention/search work largely treats negative evidence as present/absent or sufficient/insufficient; we test whether language models represent the observation process that determines how much a non-observation should count as evidence.**

Adjacent work on search overuse and abstention does not answer the detectability question. The contribution must therefore remain about **informative absence**, not generic uncertainty or abstention.

## Expected headline findings

A Main-paper package could support findings such as:

1. belief updates are / are not monotone in expected detectability under content-matched null observations;
2. models confuse **search effort** with **search sensitivity**, revealing a specific heuristic rather than Bayesian negative-evidence integration;
3. multiple failed searches are over-counted when their coverage overlaps, linking negative evidence to evidence dependence;
4. the same failure predicts premature stopping or endless over-search in tool-using agents.

## Method runway

### Method family

**Observation-Model-Aware / Expected-Detection-Calibrated Search Controller**

Instead of representing `not found` as a Boolean event, the agent maintains an estimate of:

```text
coverage / sensitivity / false-negative rate
→ expected probability of observing evidence if H were true
→ likelihood contribution of a null result
```

This signal controls:

- belief update;
- whether to keep searching;
- whether to abstain;
- whether “not found” can be upgraded to “evidence against”.

### Why the method follows from the science

If the behavioral study shows that models ignore or miscalibrate expected detectability, the method directly inserts the missing observation-model variable. It is not a generic prompt or confidence calibration trick.

### Method success criterion

- calibrated belief updates against known generative ground truth;
- fewer unjustified `not found -> false` claims;
- fewer wasteful searches when cumulative independent detectability is already high;
- correct continued search when absence is still uninformative.

## Frozen G0

Programmatically generate scenarios with fixed prior and null observation while varying `P(detect evidence | H=true)`.

Primary first-shot test:

```text
higher expected detectability
→ stronger negative belief update
```

Test ordinal monotonicity before exact numerical calibration.

## Null interpretation

A null is meaningful: the tested reasoner fails to distinguish **search failure** from **evidence of absence** even when the observation process is completely specified.

## Verdict

`STRONG_KEEP / MAIN_SCALE / NOVELTY_STRONG / METHOD_OPENING_VERY_STRONG / LOW_PREREQUISITE_TAX`

# Candidate 2 — Same Evidence, Different Sampling Process

## Mother question

**Do language models condition inductive generalization on why the observed examples were selected, or do they treat evidence only as a bag of observed examples?**

## External construct

Identical observations can rationally support different hypotheses under different data-generating / sampling processes. Classical work distinguishes strong/property sampling from weak/category sampling, and recent human studies show that people can even reinterpret already-seen data when the sampling frame is revealed, retracted, or replaced later.

## ACL / EMNLP / NAACL scope verdict

`MAIN_SCALE`

It would be too narrow as one property-induction prompt comparison. The Main-scale version is a unified study of **selection-process-sensitive inference**:

1. same exemplars under strong vs weak sampling;
2. sampling frame before vs after evidence;
3. retraction / replacement of an initially wrong sampling frame;
4. transfer from synthetic induction to ICL / retrieved demonstrations where the selector itself determines evidential meaning.

## Unique novelty package

### Closest collision

ICL literature has a large body of work on demonstration selection: retrieval, diversity, influence, learned selection, etc. This does **not** answer the proposed question.

### Unique narrative

> **Existing ICL work asks which examples should be selected; the proposed work asks whether the selection policy itself is part of the evidence once those examples are observed.**

This distinction is the core novelty and must stay explicit throughout the paper.

### Novelty type

- old question, new answer;
- scientific reframing;
- new factor decomposition for ICL evidence.

## Expected headline findings

1. content-matched examples yield different generalization only when sampling intent/process is represented appropriately;
2. models may respond when sampling frame is stated before the examples but fail to reinterpret old evidence when it is revealed later;
3. retraction can expose persistence / anchoring in the assumed selection process;
4. retrieval-selected ICL examples can systematically bias inference when the model ignores the selector's sampling policy.

## Method runway

### Method family

**Selection-Aware ICL / Sampling-Process-Aware Demonstration Reasoner**

A selector/retriever should expose or allow inference of the selection process, and the reasoner should evaluate demonstrations under:

```text
P(example | hypothesis, selection policy)
```

rather than conditioning only on example contents.

Practical variants:

- retriever emits selection metadata;
- learned selector model estimates inclusion probabilities;
- reasoning module reweights demonstrations by selection likelihood;
- latent sampling-frame variable is jointly inferred when policy is unknown.

### Why the method follows

If the study shows that identical demonstrations are misinterpreted because the selection process is ignored, the remedy is to make the selection mechanism explicit in inference—not merely choose “better examples.”

### Success criterion

- calibrated generalization under content-matched changes in sampling policy;
- robustness to curated vs random vs retrieval-selected vs adversarially selected examples;
- improved transfer when the selector changes at deployment time.

## Frozen G0

Programmatically generate one-dimensional concepts with analytically different strong- and weak-sampling posteriors. Keep observed exemplars identical and alter only the stated selection process.

## Null interpretation

A null is meaningful: the model behaves as if observations have evidential value independent of the process that generated them.

## Verdict

`STRONG_KEEP / MAIN_SCALE / UNIQUE_NARRATIVE_STRONG / METHOD_OPENING_STRONG / COLLISION_MEDIUM_BUT_DISTINCT`

# Candidate 3 — The Same Fit Is Not the Same Evidence

## Mother question

**Do language models understand that evidence used to discover / select a hypothesis has different confirmatory force from independent evidence used to test it?**

## External construct

Selective inference, double dipping, HARKing, and post-hoc accommodation all reflect the same underlying structure: the hypothesis-selection process changes the evidential meaning of the final reported fit.

## Fresh collision audit

This lane is more occupied than the first Round-16 pass suggested:

- AI-scientist auditing work already identifies **post-hoc selection bias** as a failure mode and shows that workflow logs help detect it;
- current work also proposes selection-aware protocols for adaptive benchmark / prompt search;
- LLM p-hacking and preregistration are active topics.

Therefore the paper cannot be “AI scientists p-hack” or “post-hoc selection is bad.”

## ACL / EMNLP / NAACL scope verdict

`MAIN_SCALE`, but only under the following distinct formulation.

### Unique narrative after collision

> **Existing work primarily detects bad workflow or corrects adaptive evaluation externally. We ask whether the language model itself assigns quantitatively different epistemic weight to the same reported result when the hypothesis-selection history changes.**

This is **epistemic appraisal of selection history**, not p-hacking detection.

## Novelty package

### Novelty type

- old question, new answer;
- new measurement / formulation;
- AI-scientist reliability diagnosis.

### Required factors

1. **search multiplicity:** M candidate hypotheses before choosing the winner;
2. **data reuse:** same data for discovery and confirmation vs independent holdout;
3. **implicit vs explicit selection history:** remove shortcut words such as `p-hacking`, `preregistered`, `post hoc`;
4. **downstream scientific decision:** accept evidence, request replication, or collect fresh data.

## Expected headline findings

1. whether evidential confidence discounts continuously with search space M rather than applying a binary “post-hoc” stigma;
2. whether models distinguish independent confirmation from same-data re-evaluation at matched headline statistics;
3. whether they still account for selection when the workflow is described neutrally without methodological buzzwords;
4. whether selection-history awareness predicts reliable reviewer / scientist actions.

## Method runway

### Method family

**Selection-History-Aware Scientific Verifier / Discovery–Confirmation Ledger**

Maintain explicit lineage linking:

```text
hypothesis
↔ data that generated/selected it
↔ search space / attempts
↔ independent confirmatory data
```

Then compute / learn a selection-aware evidence score and require fresh confirmation when point identification is invalid.

### Distinction from current methods

The method must not be sold as generic preregistration or log auditing. Its unique role is **quantitative evidential appraisal conditional on selection history**.

### Success criterion

- does not give equal confirmatory credit to a pre-specified hypothesis and a selected winner with the same final statistic;
- correctly scales discount with search multiplicity;
- triggers holdout/replication only when needed;
- improves scientific-agent calibration without blanket distrust of exploratory work.

## Frozen G0

Synthetic null process; select the best statistic from M hypotheses while matching final reported score across conditions. Compare `M=1,2,5,10,50,100`, plus discovery-on-D1/confirmation-on-D2 vs discovery-and-confirmation-on-D1.

## Verdict

`KEEP / MAIN_SCALE / COLLISION_MEDIUM_HIGH / UNIQUE_NARRATIVE_SURVIVES / METHOD_OPENING_STRONG`

This is not as clean as Candidates 1–2, but it still has a defensible independent paper narrative.

# Candidate 4 — Agreement Is Not Corroboration

## Mother question

**Do language models understand evidence dependence itself, rather than merely count agreeing reports?**

## External construct

The epistemic value of agreement depends on whether reports are independent observations or descendants of a shared source.

## Fresh collision audit — major downgrade

A very recent Aug-2026 paper, **Beyond Memory Majority: Latent-Source Reasoning for Multi-Agent Memory Arbitration**, now explicitly studies correlated memories that inherit shared upstream sources, calls out false majorities, estimates the effective number of independent evidence sources using neural dependency inference plus provenance priors, and proposes active recovery of independent evidence.

Independent 2026 work also argues that source independence itself is a measurable property of evidentiary provenance.

Thus the following narrative is no longer sufficiently unique:

```text
correlated evidence gets double-counted
→ estimate independent evidence roots
→ provenance-aware aggregation
```

That would collide both scientifically and methodologically.

## ACL / EMNLP / NAACL scope verdict

`MAIN_SCALE` in abstract, but `BORDERLINE_AFTER_COLLISION` as a new paper.

It survives only if reframed away from memory arbitration and toward **epistemic competence under content-matched evidence**:

1. explicit vs implicit provenance;
2. dependence topology while report contents/count remain fixed;
3. dependence × source reliability interaction;
4. principle–behavior gap: can a model verbalize source independence yet fail to use it when integrating evidence?

## Unique novelty package

### Defensible narrative

> **Do language models possess a general, transferable concept of evidential dependence that controls belief revision, or do existing provenance-aware systems need to supply that structure externally?**

This is different from building an aggregator, but the distance is now smaller than before.

## Method runway

A generic provenance-aware aggregator is no longer novel enough.

The only interesting method direction is a **provenance-contrastive epistemic reasoner** trained on content-matched pairs that differ only in dependence structure, with the aim of teaching the model to infer and use latent lineage even when provenance is only implicit.

Potential success tests:

- transfer to unseen dependency graph topology;
- implicit paraphrased lineage rather than explicit citation IDs;
- interaction with reliability calibrated correctly;
- behavior improves without external symbolic provenance labels at test time.

## Verdict

`BORDERLINE_KEEP / WATCH+ / MAIN_SCALE_BUT_COLLISION_HIGH / METHOD_COLLISION_HIGH`

This topic is no longer a top recommendation. User selection would require accepting a visibly more crowded narrative.

# Candidate 5 — Missingness Is Data (replacement)

## Working title

**Missingness Is Data: Do Language Models Reason About Why Values Are Missing Before Drawing Conclusions?**

Alternative framing:

**Same Observed Table, Different Missingness Process: What Can an LLM Data Analyst Validly Infer?**

## External construct

In statistics, missingness is not merely a preprocessing nuisance. MCAR, MAR, and MNAR encode different assumptions about the process producing missing values, with different consequences for bias, ignorability, and identifiability. In general MNAR settings, the full-data distribution may not be identifiable from the observed data without additional assumptions.

## Closest current work

2026 work already benchmarks LLMs as missing-value **imputers** under MCAR/MAR/MNAR. A recent clinical study also asks closed LLMs to infer missingness mechanisms and generate preprocessing code.

Therefore the novelty cannot be:

```text
LLMs can impute missing values
LLMs can classify MCAR/MAR/MNAR
LLMs can write data-cleaning code
```

## Unique narrative after collision

> **Existing LLM missing-data work asks how well models fill in missing values. We ask whether LLM data-analysis agents understand that the mechanism producing missingness changes what can be validly inferred—even when the observed table and missing mask look the same.**

The core object is **inferential validity / ignorability / identifiability**, not imputation accuracy.

## ACL / EMNLP / NAACL scope verdict

`MAIN_SCALE`

The ACL-family venue fit is credible because NAACL 2025 has main-track LLM data-analysis agents and ACL 2026 includes machine-learning/data-analysis agents and substantial tabular reasoning work.

The coherent full-paper package is:

1. **mechanism-conditioned inference:** MCAR/MAR/MNAR under controlled data generators;
2. **same observed data, different collection process:** natural-language descriptions of how missingness arose change which estimands/methods are valid;
3. **identifiability awareness:** under MNAR, does the agent falsely emit a confident point estimate or request assumptions / sensitivity analysis / bounds?;
4. **end-to-end executable analysis:** does correct missingness reasoning reduce downstream estimation bias and invalid conclusions?

## Novelty package

### Novelty type

- old statistical question, new answer;
- system diagnosis;
- factor decomposition;
- principled method derived from analysis.

### Novelty one-liner

> **The problem is not whether LLMs can impute missing values; it is whether they reason about the process that made values missing before deciding what inference is statistically justified.**

## Competing explanations

1. **Impute-first heuristic:** fill every blank, then analyze as if complete;
2. **mechanism-label heuristic:** recognize the words MCAR/MAR/MNAR but fail to change inference;
3. **pattern heuristic:** infer missingness only from the mask / observed correlations;
4. **missingness-aware inference:** use collection-process assumptions to choose valid estimators or recognize non-identifiability.

## Method runway

### Method family

**Missingness-Aware Data Analysis Agent**

Pipeline:

```text
natural-language data-collection process + observed table
→ missingness / causal assumption graph
→ ignorability / identifiability check
→ choose deletion / conditional imputation / IPW / joint modeling / sensitivity analysis / bounds / abstention
→ execute analysis
```

For MNAR/non-identified settings the method should not hallucinate a single answer; it should expose assumptions, compute sensitivity ranges/bounds, or request additional information.

### Why the method follows

If models are shown to classify missingness but still perform invalid inference, the missing component is not another imputer—it is a **pre-analysis assumption and identifiability layer**.

### Success criterion

- lower estimation bias on synthetic complete-data ground truth;
- correct method choice under MCAR/MAR;
- correct refusal of unjustified point identification under MNAR;
- calibrated sensitivity/bounds when assumptions vary;
- transfer from synthetic tables to natural data-analysis scenarios.

## Frozen G0

Construct small synthetic tabular generators with known complete-data estimands and controlled missingness mechanisms. Evaluate open models on two distinct tasks:

1. choose / justify an analysis procedure;
2. produce an executable estimate or explicitly state non-identifiability.

A particularly strong paired cell uses the same observed rows/mask while the natural-language data-collection mechanism differs; the correct inferential action changes despite similar surface data.

## Null interpretation

A null is meaningful: the model treats missing values as cells to reconstruct rather than information about the data-generating process and inferential assumptions.

## Verdict

`KEEP / MAIN_SCALE / NOVELTY_MEDIUM_STRONG / METHOD_OPENING_VERY_STRONG / COLLISION_MANAGEABLE`

This is a stronger fifth candidate than Blocking under the current README standard.

# KILLED — Kamin Blocking / Cue Competition

## Why it was initially attractive

Kamin blocking is a natural classic associative-learning construct and can be tested cheaply with synthetic contexts.

## Why it is now killed

The problem is not an exact-collision technicality. The **novelty package after collision becomes too small for ACL/EMNLP/NAACL Main**:

- NeurIPS 2025 already establishes LLMs as model organisms for human associative learning;
- EMNLP 2025 explicitly brings Rescorla–Wagner into LLM mixed-context behavior and proposes RW-based steering;
- adding classical blocking/unblocking/overshadowing would become another signature inside an already-occupied associative-learning narrative;
- the natural method opening (prediction-error/context weighting/steering) also overlaps existing work.

The only way to save it would be to keep narrowing the scientific claim to “this particular classical signature has not been measured,” which violates the README collision rule.

## Final status

`KILL / TOO_NARROW_AFTER_COLLISION / METHOD_COLLISION_HIGH`

# Search lessons from this deep audit

1. **No exact collision is not enough.** Blocking is the clearest example: the exact classical experiment may be absent, yet the surrounding narrative and method family are occupied enough that the remaining paper would be too incremental.
2. **A good collision can sharpen rather than kill.** Sampling-process reasoning survives because demonstration-selection work asks a different question (`which examples?`) from the proposed epistemic question (`why were these examples selected, and how should that change inference?`).
3. **Method runway can expose hidden collision.** Source dependence looked excellent until a new provenance-aware method paper appeared; once the same diagnosis naturally produced almost the same method, the unique contribution shrank sharply.
4. **Main-scale breadth must come from one construct across complementary manipulations.** Informative absence is not made broad by adding benchmarks; it becomes Main-scale through detectability, overlapping search coverage, sequential negative evidence, and agent stopping—all manifestations of the same observation-model principle.
5. **Replacement topics must beat killed topics on all three axes.** Missingness replaces Blocking because it has a stronger external construct, a distinct inferential question despite existing imputation papers, and a much clearer method opening.
