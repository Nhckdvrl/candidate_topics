# 1. Annotation Policy Is Part of the Task

## Mother question

**When two NLP datasets claim to represent the same task, how much apparent cross-dataset failure comes from domain shift, and how much comes from a change in the task definition encoded by annotation policy?**

## External object

Annotation policy is part of the data-generating process. The same text may legitimately receive different labels under different span rules, ambiguity policies, scope definitions, taxonomies, cultural conventions, or operational definitions.

This problem existed long before LLMs. LLMs create a new handle because annotation guidelines can now be supplied, inferred, compared, and conditioned on directly at inference time.

## ACL / EMNLP / NAACL Main package

A full paper should unify:

1. **domain shift vs task-definition shift decomposition** under matched examples;
2. **policy recovery** from guidelines + small example sets;
3. **policy-conditioned prediction** where the same instance changes label under two valid policies;
4. **cross-dataset harmonization** without forcing all corpora into one supposedly canonical gold definition;
5. **boundary condition:** distinguish genuine semantic disagreement from policy-induced disagreement.

## Novelty package

Adjacent work studies guideline following, schema harmonization, annotation mismatch, and model priors. The narrative that remains ours is:

> **Cross-dataset generalization should explicitly decompose content/domain shift from task-definition shift, and annotation policy should be treated as an explicit latent task variable rather than invisible noise in gold labels.**

This is broader than “guidelines matter” and more NLP-native than a generic robustness study.

## Method runway

**Policy-Conditioned NLP / Annotation-Policy Harmonization**

```text
instance
+ explicit or inferred annotation policy
+ target label ontology
→ policy-conditioned prediction
```

For multi-corpus training, learn mappings between a latent semantic construct and policy-specific outputs instead of collapsing policies into a single label space.

## G0

Use 2–3 existing tasks with documented cross-corpus guideline differences. Construct matched instances where semantics are held fixed but policy-derived labels differ. Test whether open models switch correctly when only the policy changes.

## Verdict

`STRONG_KEEP / NLP_NATIVE / MAIN_SCALE / METHOD_RUNWAY_VERY_STRONG`

# 2. Controls Are Tests of Assumptions

## Mother question

**Can an LLM scientific reasoner identify what assumption an experimental control probes, determine whether the control is valid, and update the main claim correctly when the control passes or fails?**

## External object

Negative controls, placebo tests, positive controls, falsification outcomes, and control populations are classical scientific-method constructs. Their evidential value depends on which assumption they test—not on the surface fact that they are called “controls.”

## Main-scale package

1. **control selection** for a stated threat;
2. **control validity**;
3. **pass/fail interpretation**;
4. **control generation and transfer** across domains.

Core factorization:

```text
no direct treatment effect
× shared relevant bias/confounding pathway
× sufficient diagnostic sensitivity
```

## Novelty package

AI-scientist work already asks whether agents can propose experiments or falsify hypotheses. The distinct narrative is:

> **Do LLMs understand controls as semantic/causal tests of specific assumptions, rather than as stereotyped auxiliary experiments?**

This creates a coherent explanation layer between experiment planning and valid inference.

## Method runway

**Control-Aware Scientific Critic / Experiment Designer**

Bind each proposed control to:

```text
main claim
→ threatened assumption
→ required invariance/no-effect property
→ shared bias mechanism
→ expected diagnostic power
```

Then reject invalid controls, propose assumption-targeted controls, and interpret pass/fail conservatively.

## G0

Programmatic causal graphs plus natural-language studies with exact labels: valid controls, treatment-affected invalid controls, controls without the shared confounder, and diagnostically weak controls.

## Verdict

`STRONG_KEEP / MAIN_SCALE / UNIQUE_NARRATIVE_STRONG / METHOD_RUNWAY_VERY_STRONG`

# 3. Rebutting Is Not Undercutting

## Working title

**Rebutting Is Not Undercutting: Do Language Models Distinguish Attacks on a Claim from Attacks on Its Evidential Link?**

## Mother question

**When new information defeats an argument, does an LLM distinguish evidence that supports the opposite conclusion from evidence that only weakens the connection between the original premise and conclusion?**

## External object

In classical defeasible reasoning and argumentation theory, a **rebutting defeater** provides reason to deny the conclusion, while an **undercutting defeater** attacks the inferential link from premise to conclusion without necessarily supporting the opposite conclusion.

This distinction is old, well-defined, and independent of LLMs. Argument-mining work already treats undercuts as a distinct argumentative relation, but they remain substantially less studied than direct attacks.

## Collision audit

NAACL 2025 DEFREASING establishes broad LLM defeasible-reasoning evaluation. Argument-mining work has also introduced a real-world undercut dataset and undercut recognition models.

Those works do **not** fully answer the proposed mother question:

- can an LLM use the distinction in **belief revision**, not merely classify relation labels?;
- does it preserve the original conclusion as possible after an undercut, while appropriately weakening its support?;
- can it choose a different reasoning/action response depending on whether the attack targets the claim, premise, or inferential link?

The narrative must remain about **epistemic operation / attack target**, not “first LLM undercut classifier.”

## ACL / EMNLP / NAACL Main package

1. **recognition:** rebutting vs undercutting vs undermining under matched semantics;
2. **belief update:** how each attack type should change confidence in conclusion, premise, and inference separately;
3. **argument continuation:** what counterargument/revision is appropriate after each defeater type;
4. **real-world transfer:** existing argument-mining corpora plus controlled synthetic argument graphs;
5. **boundary:** explicit lexical markers vs implicit attack relations.

## Novelty package

> **Broad defeasible-reasoning work asks whether models revise conclusions when exceptions appear. We ask whether models represent *where* an argument is defeated—claim, premise, or inferential link—and whether that structural distinction governs belief revision and response.**

This is a classic NLP/argumentation question reopened by generative LMs.

## Method runway

**Defeater-Aware Argument Reasoner / Evidence-Graph Update**

Represent arguments as:

```text
premise nodes
→ support/warrant edge
→ conclusion node
```

and attach incoming attacks to the correct target. The system then updates only the affected part of the graph, rather than treating every counterargument as direct contradiction.

Possible methods include attack-target-aware decoding, structured argument memory, or training objectives that distinguish conclusion attack from support-link attack.

## G0

Programmatically generate matched argument triples where only the attack target changes, with exact formal labels. Then validate on existing real-world undercut annotations. No new large-scale manual annotation is required.

## Verdict

`NEW_STRONG_KEEP / MAIN_SCALE / NLP_NATIVE / METHOD_RUNWAY_VERY_STRONG / COLLISION_MANAGEABLE`

# 4. Missingness Is Data

## Mother question

**Does an LLM data-analysis agent understand that the process producing missing values changes which analyses, estimands, and conclusions are valid—even when the visible incomplete table is identical?**

## External object

MCAR/MAR/MNAR and related missing-data theory concern the data-generating process, ignorability, recoverability, and identifiability. Missingness is not simply a cell-filling problem.

## Main-scale package

1. same visible table/mask, different missingness process;
2. missingness mechanism × analysis choice;
3. mechanism × target estimand;
4. identifiability boundary: point estimate vs bounds/sensitivity/ask-for-more-data.

## Novelty package

Recent LLM work mainly studies missing-value imputation or prediction with missing inputs. The distinct story is:

> **Can LLM analysts reason about the inferential consequences of why data are missing, rather than treating missingness as a reconstruction problem?**

## Method runway

**Missingness-Mechanism-Aware Data Analysis Agent / Identifiability Gate**

Infer or receive a missingness graph, identify the target estimand, determine ignorability/recoverability, and route to a valid estimator, sensitivity analysis, bounds, more-data request, or abstention.

## G0

Synthetic complete data with known ground truth and controlled missingness mechanisms. Exact labels for valid analyses and identifiability; no human annotation needed.

## Verdict

`STRONG_KEEP / MAIN_SCALE / NOVELTY_STRONG_VS_IMPUTATION / METHOD_RUNWAY_VERY_STRONG`

# 5. Same Study, Different Population

## Mother question

**Given internally valid evidence from a source population, can an LLM determine whether and how the result should be transported to a different target population?**

## External object

External validity / transportability is a mature causal-inference problem. A source/target population difference matters when it changes effect modifiers, causal mechanisms, or support/positivity—not merely because two groups look demographically different.

## Main-scale package

1. **effect-modifier awareness**;
2. **irrelevant covariate shift vs true effect-modifier shift**;
3. **support/positivity violations**;
4. **multi-study synthesis for a target population**;
5. explicit vs inferable vs missing transportability information.

## Novelty package

Existing evidence-synthesis systems largely extract/aggregate trial results or use population/eligibility similarity. The distinct narrative is:

> **Do language models understand the causal conditions under which evidence from one population applies to another, rather than relying on surface similarity?**

## Method runway

**Transportability-Aware Evidence Synthesis Agent**

Extract candidate effect modifiers, represent source-target structural differences, check support/positivity, reweight/standardize when valid, and request target data or abstain when transport is not identified.

## G0

Synthetic randomized studies with analytically known heterogeneous effects. Hold source estimate and overall source-target mismatch magnitude fixed while switching whether the shifted variable is irrelevant or a genuine effect modifier.

## Verdict

`STRONG_KEEP / MAIN_SCALE / NOVELTY_STRONG / METHOD_RUNWAY_VERY_STRONG`
