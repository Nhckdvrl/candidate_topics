# Round 07 — ACL-first aggressive search, feasibility-first survival audit

Date: 2026-08-23

## 0. Objective

Round 07 is deliberately adversarial. We search broadly, but **assume every candidate is dead until it passes feasibility and collision audit**.

Primary policy:

- primary seeds: CCF A/B AI / NLP venues only;
- ACL main/long first;
- NAACL / EMNLP next;
- NeurIPS / ICML / AAAI / IJCAI only when the object is directly relevant to LLM/NLP/AI;
- EACL is not eligible as a primary seed;
- little/no paid API dependence for G0;
- no large new manual annotation prerequisite;
- local open-weight models preferred;
- GPU-heavy mechanism is an advantage **after** the behavioral object is frozen;
- promotion requires same-model phenomenon + artifact + automatic labels + a bounded causal question.

The ideal shape remains:

```text
published, strong phenomenon
+ accessible open model
+ public data / prompts / evaluator
+ exact or programmatic labels
+ dense matched critical cell
+ an unresolved scientific distinction
```

Anti-pattern:

> `published behavior → add probe/SAE/patching → call it mechanism`

That is not enough. The intervention must answer a scientific distinction that the seed does not already close.

# 1. Existing survivors re-audited

## 1.1 SemTrace — KEEP / #1

Seed: ACL 2026 main, *Sense and Sensitivity: Examining the Influence of Semantic Recall on Long Context Code Understanding*.

Still the cleanest object in the pool:

```text
same model
same synthetic program
same computation
move only the relevant code position
```

The paper reports severe middle-position degradation for semantic execution while lexical recall is much less position-sensitive. The synthetic generator makes intermediate program states exactly computable.

The defensible question is **not** generic state tracking or generic lost-in-the-middle:

> **Why does context position selectively break operational state computation while lexical access to the same code survives?**

Frozen critical cell:

```text
edge semantic = correct
middle semantic = wrong
edge lexical = correct
middle lexical = correct
```

Only this cell justifies mechanism work.

Verdict: `ACTIVE / SURVIVAL_TOP / #1`.

# 2. PROMOTED: ChronoScope — reference-time state loss or failure to use it?

Seed: ACL 2026 main, *Evaluating Temporal Consistency in Multi-Turn Language Models*.

Paper:

- https://aclanthology.org/2026.acl-long.2133/
- official repo: https://github.com/yashkumaratri/ChronoScope

## 2.1 Why this survived the audit

ChronoScope contains >1.4M deterministically generated temporal question chains grounded in Wikidata. It separates:

- Gold Context (previous assistant turns replaced by gold answers);
- Self-Conditioned context;
- Questions Only.

The official local evaluator already supports accessible open models including:

- Qwen2.5-7B-Instruct;
- Qwen3-4B-Instruct;
- Llama-3.1-8B-Instruct;
- Mistral-7B-Instruct;
- Gemma-7B-IT;
- GPT-OSS-20B;
- others.

Most importantly, the evaluator stores `present_day_answer` and defines a `drift` error when:

```text
prediction != historical gold
AND
prediction == valid present-day truth
```

So “drift back to the present” is not a subjective post-hoc category.

The paper reports that models can answer temporally explicit questions correctly, yet degrade sharply when the temporal scope must be carried implicitly across turns; present-day substitution is a dominant error mode and persists under Gold Context. Thus the failure cannot be reduced to previous assistant error propagation.

## 2.2 Old scientific question × LLM-era handle

Reference time is a classical problem in temporal/discourse semantics. The relevant old distinction is not “does the model know an old fact?” but:

> **Is a conversational reference-time state actually maintained across discourse, and if maintained, does it control retrieval/readout against a stronger default present-time prior?**

LLMs let us inspect this state layer-by-layer and intervene on it directly.

## 2.3 Research question

> **When a model drifts from an established historical scope back to a present-day answer, has the conversational reference-time state been lost, or is it still represented but fails to override present-day parametric knowledge?**

This gives a concrete computation split:

```text
reference-time establishment
→ state maintenance across turns
→ binding time scope to queried relation/entity
→ competition with present-day parametric answer
→ output
```

## 2.4 Frozen prerequisite

Do **not** start with probes.

Use the official Gold Context evaluator and require a high-density event:

```text
same chain + same model
initial explicit temporal turn = correct
later implicit-scope turn = wrong
wrong answer = official present_day_answer
```

This rules out:

- missing historical knowledge;
- error propagation from model-written previous turns;
- arbitrary hallucination.

Existing frozen screen added in Round 07:

```text
advisor_topic_search/g0/chronoscope_drift_g0.py
```

The script consumes the official evaluator JSON and reports chain-level and turn-level density by family/position. It refuses partial dumps when example coverage is too low.

## 2.5 Mechanism only after G0

If the cell is dense:

1. freeze one open model and one/two chain families (start with carryover);
2. construct a matched explicit-restatement counterpart to the same follow-up;
3. decode/reference the target year or temporal scope at a pre-registered small set of token locations/layers;
4. compare implicit-drift vs explicit-correct pairs;
5. only then use natural counterfactual activation patching from explicit-correct → implicit-drift;
6. test whether rescuing temporal state changes the output from present-day answer to historical gold.

The preferred causal claim is **not** “there is a year direction”. It is:

> intervention on the conversational reference-time state specifically rescues temporally scoped source selection.

## 2.6 Collision audit

Nearby work exists on:

- general temporal QA;
- long-context temporal/event order memory;
- parametric-vs-contextual knowledge reconciliation;
- conversational degradation.

But the search did not find an exact work that causally studies **implicit conversational reference-time state vs present-day parametric default** on matched ChronoScope-style turns.

Important boundary:

- generic context-vs-parametric conflict is already mechanistically crowded;
- generic multi-turn memory is crowded;
- generic temporal representation is not enough.

Novelty must stay on the specific reference-time state and its causal use in temporal source selection.

## 2.7 Kill lines

Kill or demote if:

- first-correct → later-present-drift is sparse on Qwen/Llama open models;
- drift disappears under Gold Context;
- explicit-restatement does not rescue the exact same follow-up instances;
- year/scope decoding only works by reading lexical year tokens and does not distinguish maintained implicit state;
- intervention requires broad layer/strength fishing;
- result reduces to generic context-vs-parametric competition already explained by existing knowledge-conflict work.

Verdict: `ACTIVE / SURVIVAL_TOP / #2 / RUN_DRIFT_G0`.

# 3. New Round-07 deep-audit candidates

## 3.1 Table DRE — structure understood, wrong value referenced

Seed: ACL 2026 main, *When LLMs Read Tables Carelessly: Measuring and Reducing Data Referencing Errors*.

Potential question:

> **When table structure is intact but a wrong cell value is cited, is the failure in localization, entity–value binding, or late readout substitution?**

Pros:

- structured/exact row-column-value labels;
- local perturbations possible;
- open-size models;
- critical cell can be defined as structure-correct/reference-wrong.

Risk: entity binding and positional binding mechanisms are already mature. Unless the table-specific reference failure is demonstrably distinct, this becomes “binding mechanism applied to tables”.

Verdict: `DEEP_AUDIT / ARTIFACT_AND_COLLISION_GATE`.

## 3.3 Answering the Wrong Question — query-state drift

Seed: ACL 2026 main, *Answering the Wrong Question: Reasoning Trace Inversion for Abstention in LLMs*.

Attractive observation: some failures can be interpreted as the reasoning trace effectively solving a different question than the original query.

Natural mechanism question:

> **During a wrong-question failure, when does the representation of the original query cease to control the reasoning trajectory?**

Why not promoted:

- the “question actually answered by the trace” is reconstructed/inferred from generated reasoning, not a programmatically exact latent variable;
- query/instruction forgetting during long reasoning is an increasingly crowded area;
- a causal G0 would require a reliable independent definition of query-state preservation before mechanism.

Verdict: `WATCH+ / CONSTRUCT_GATE`.

## 3.4 Belief consistency — stability vs correctness

Seed: ACL 2026 main, *Assessing Belief Consistency on the Logical Conversation Process*.

Interesting dissociation: code/math continued-pretraining families can improve belief consistency while logical failure increases.

Old question:

> **Does training improve belief-state persistence, or merely make the model more stubbornly committed to a state even when that state is wrong?**

Why not promoted:

- no clean official code artifact found;
- evaluation is sampling-heavy (paper uses very large repeated generation counts);
- model-family comparisons are not clean parent-child interventions and authors themselves caution relationship assumptions;
- prompt-bias sensitivity matters.

Verdict: `WATCH / STABILITY_VS_CORRECTNESS`.

## 3.5 Illusions of Confidence — stable answer vs robust belief

ACL 2026 work shows that perfect self-consistency can coexist with severe vulnerability to peer/authority interference.

This is a clean old calibration/robust-belief distinction, but the natural next step risks becoming “probe robust vs brittle beliefs and steer them”. No specific computation bottleneck is yet forced by the seed.

Verdict: `WATCH+`, not ACTIVE.

## 3.6 GSM-Infinite — computation cliff

ICML 2025 GSM-Infinite is attractive as an engineering resource:

- unlimited synthetic data;
- exact answers;
- controllable dependency complexity;
- no annotation/API dependence.

Potential question:

> near the reasoning-complexity cliff, are intermediate node values still correctly represented but no longer propagated through the next dependency edge?

Why not promoted:

- generic state-tracking / multi-hop computation mechanism is already crowded;
- this could collapse into SemTrace-like state analysis without a genuinely distinct scientific claim.

## 3.7 Interpretable Traces, Unexpected Outcomes — correct trace, wrong final answer

ACL 2026 reports very high-density `correct intermediate trace → wrong final answer` cells in some small open models after SFT.

This is a real dissociation, but CoT faithfulness / hidden computation / reasonless intermediate-token work is already highly crowded. A generic “why does correct trace not control answer?” mechanism is unlikely to beat current ACTIVE candidates without a much sharper causal distinction.

Verdict: `WATCH+ / COLLISION_HEAVY`.

## 3.8 Emergent Response Planning — plan commitment vs plan revision

ICML 2025 shows that pre-output hidden states predict global properties of a future response. The seed leaves causal planning questions open.

A sharper possible follow-up is:

> **Is the pre-output answer plan a commitment that controls later generation, or a provisional state that is repeatedly rewritten as evidence/reasoning unfolds?**

Why not promoted:

- generic latent planning / steering is already receiving rapid follow-up, including refusal planning and internal-behavior prediction;
- we do not yet have a natural exact paired dataset of planned-answer reversals that makes the dynamic-rewrite question easy to identify.

Verdict: `WATCH+ / NEED_EXACT_TRANSITION_OBJECT`.

## 3.9 Experience-following in agent memory — proactive interference

ACL 2026 *How Memory Management Impacts LLM Agents* reports that retrieved similar past experiences strongly shape current outputs and can propagate erroneous experiences.

Possible old-memory question:

> **Does a misleading retrieved episode corrupt the current task representation, or leave task state intact while hijacking action readout?**

Why not promoted:

- agent memory / ICL retrieval behavior is crowded;
- official artifacts are less clean than ChronoScope/SemTrace;
- generic similar-demo following is a plausible simpler explanation.

Verdict: `WATCH`.

## 3.10 NeurIPS associative-learning model organism — repetition/forgetting

NeurIPS 2025 uses open LMs as model organisms for human associative learning and reports encoding/consolidation/forgetting-like phases.

Advisor-fit is high, but generic “why does repetition eventually cause forgetting/degradation?” collides with earlier long-context repetition degradation and mechanistic repeated-token work. The forgetting regime is also model-specific / late for some models.

Verdict: `WATCH / OLD_PROBLEM_BUT_COLLIDED`.

# 7. Round-07 lesson

Aggressive search still produced many papers with attractive anomalies. Most die for one of four reasons:

1. the seed already contains the natural mechanism;
2. the next step is only “add a probe/patching method”;
3. the scientific construct requires too many rescue controls;
4. the artifact/model regime is not complete enough to isolate the new question.

ChronoScope survives because its new question is both old and concrete:

> **Does conversational reference time disappear, or remain internally available but lose the competition against a default present-day prior?**

The first experiment tests this exact object, not whether a new object can be manufactured.

That is the standard future rounds should keep.
