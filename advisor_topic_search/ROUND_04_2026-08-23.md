# Advisor Topic Search — Round 04 (2026-08-23)

## Objective: feasibility before elegance

This round changes the ranking criterion again, deliberately.

After nearly twenty candidate projects, the dominant failure mode is no longer that we cannot generate interesting questions. We can. The problem is that too many candidates require us to first discover that the experimental object exists, then discover a workable model, then repair the measurement, and only then test the scientific claim.

For topic selection, this is too much stacked uncertainty.

Therefore Round 04 uses a stricter rule:

> **A strong candidate should inherit as much experimental reality as possible from the seed paper. We should spend our research risk on one new scientific question, not on recreating the object that makes the question meaningful.**

The ideal project now looks like:

```text
published phenomenon already strong
+ exact open-weight model already known to exhibit it
+ released dataset
+ released scoring / reproduction code
+ automatic labels
+ useful instance-level critical cell
        ↓
one new causal / mechanistic question
        ↓
small, locked G0
        ↓
mechanistic expansion only if G0 passes
```

This is stricter than the previous `interesting + low resource cost` rule.

# 1. Feasibility-first survival gate

A candidate should not be called `TOP_POOL` merely because all experiments are technically implementable.

It must survive the following stack.

## F0 — Artifact completeness

Before designing our own experiment, verify exactly what the seed releases:

```text
data
+ model names/checkpoints
+ prompt / scoring recipe
+ code or enough details to reproduce the reported effect
```

The strongest seed gives all four.

If the paper's key phenomenon is reported only on inaccessible closed models, or the released repository does not actually contain the relevant data/code, downgrade before coding.

## F1 — Same-model prerequisite

The exact phenomenon we plan to explain must already exist, or be cheaply reproducible, in the **same open-weight model** that will be used for mechanism work.

This is a hard lesson from previous failures.

Bad:

```text
paper reports anomaly on GPT-5
→ assume Qwen-8B will instantiate it
→ build a large hidden-state pipeline
→ discover the anomaly is absent
```

Good:

```text
paper reports anomaly on Qwen3-8B
→ official code reproduces it
→ run one frozen reproduction
→ only then inspect hidden states
```

## F2 — Critical-cell density

Aggregate accuracy differences are not enough.

If the scientific question requires a dissociation such as:

```text
internal/local computation correct
BUT final behavior wrong
```

then the exact cell must occur at useful instance-level density.

No mechanism work starts until this density is measured.

If only 20 cherry-picked cases survive out of thousands, kill rather than build an explanation around them.

## F3 — Automatic ground truth

For the core G0, labels should be exact or already released:

- numeric comparison;
- diagnosis label;
- MCQ answer;
- program execution;
- known paired counterfactual target;
- released expert label.

Do not make an LLM judge the bottleneck of a mechanism project if a direct task can be chosen instead.

## F4 — One-clean-contrast mechanism

A positive intervention should have an interpretation close to the scientific question.

Preferred:

```text
same input family
same model
paired counterfactual state
one localized activation intervention
→ target decision changes
```

Dangerous:

```text
probe A + prompt B + matched subset C + steering coefficient D
+ ten exclusions
→ maybe representation X was used
```

If the causal claim needs an expanding set of controls merely to define the construct, kill under the complexity-smell rule.

## F5 — Bounded search space

Mechanistic analysis must not become layer × token × strength × prompt × model fishing.

Required protocol:

- use train/validation to select the operating point;
- lock layer/token/strength rule before test;
- evaluate once on holdout;
- keep a small number of predeclared null controls.

Recent measurement audits of activation steering make this especially important: raw steering strength, residual-stream scale, readout metric, and operating-point selection can manufacture apparently meaningful effects. Use residual-norm-comparable interventions and held-out selection when steering is used.

## F6 — Interpretable negative

Before coding, ask what a clean null means.

A good candidate should remain scientifically informative if:

- the representation is decodable but patching/steering does nothing;
- a supposed access bottleneck is actually an encoding bottleneck;
- the critical behavioral cell is absent.

If every negative can be blamed on another hidden implementation choice, the project is too flexible.

## F7 — Paper-sized expansion without changing the question

After G0, a full ACL/NAACL/EMNLP story should be reachable by adding:

- 2–4 open model families;
- a second notation/domain/task family that tests the same mechanism;
- causal intervention;
- one mitigation/method implication.

It should **not** require inventing a second unrelated phenomenon to fill the paper.

# 3. SURVIVAL TOP 1 — Representation or Access? Causally Testing the LLM Numeracy Gap

## Seed

Fengting Yuchi, Li Du, Jason Eisner. EACL 2026 Oral/Short:

**LLMs Know More About Numbers than They Can Say**

- ACL: https://aclanthology.org/2026.eacl-short.47/
- arXiv: https://arxiv.org/abs/2602.07812
- official code: https://github.com/VCY019/Numeracy-Probing

## What is already established — importantly, on our target regime

The seed uses several 7B–8B open models, including:

- Qwen3-8B;
- Llama-3.1-8B-Instruct;
- Mistral-7B;
- OLMo-2-7B-Instruct;
- DeepSeek-R1-Distill-Qwen-7B;
- DeepSeek-R1-Distill-Llama-8B.

On controlled mixed-notation comparison tasks, it reports:

```text
latent ranking probe > 90%
verbal ranking ≈ 50–70%
```

The seed also reports accurate log-magnitude information in hidden states and shows that adding a probe-aware auxiliary objective during fine-tuning improves verbal performance.

Crucially, the authors explicitly state that probing shows **representation, not usage** and that they did **not directly intervene on the representation at inference time**.

That is exactly the kind of one-step opening we want.

## Official artifact audit — unusually strong

The official repository contains:

```text
src/construct_data.py      synthetic data generation
src/get_embeds.py          hidden-state extraction
src/train_probe.py         layerwise probes
src/verbalization.py       behavioral evaluation
src/finetune.py            probe-aware LoRA experiment
scripts/*                  runnable recipes
```

The controlled data are already split into:

```text
8,000 train
1,600 validation
1,600 test
```

for each principal mixed-notation setting.

The probe implementation gives us exact representations and label construction:

```text
y = (value_a > value_b)
```

with layerwise logistic regression on the last-token state or concatenated number-token representations.

There is therefore almost no ambiguity about reproducing the seed.

## Stronger scientific framing: an old representation-vs-access question

This candidate can be grounded in a longstanding numerical-cognition debate.

Human numerical-cognition research distinguishes roughly between:

```text
representation deficit:
  the magnitude representation itself is poor

access deficit:
  magnitude representation is intact,
  but symbolic forms fail to access/use it reliably
```

The LLM seed gives us an unusually direct modern experimental handle:

- the internal magnitude/ranking representation is observable;
- the generated comparison decision is observable;
- the internal state can be causally intervened on.

So the research question becomes:

> **When an LLM has the correct numerical ordering in its hidden state but says the wrong answer, is the failure representational or an access/causal-use failure?**

This is more natural and more advisor-aligned than “let us activation-steer a number probe.”

## G-1: exact seed reproduction

Use **one model only first**: Qwen3-8B is the preferred starting point because it is already in the official recipe and is easy for us to run repeatedly.

Do not change the seed dataset.

Reproduce:

1. mixed integer/scientific comparison;
2. layerwise ranking probe;
3. verbalized ranking accuracy.

Hard prerequisite:

```text
probe accuracy >= 0.85 on held-out test
AND
verbal accuracy <= 0.75
AND
gap >= 0.15
```

The exact numeric thresholds should be frozen when the candidate is registered; the above values are reasonable screening bars, not yet a preregistration.

If the public recipe cannot reproduce a substantial gap on Qwen3-8B, stop immediately rather than moving models.

## G0: does the critical “knows but says wrong” cell exist densely?

For held-out test items define:

```text
P = frozen probe predicts correct ordering with high margin
Y = verbal output gives correct ordering
```

Critical cell:

```text
P = correct/high-margin
Y = wrong
```

This cell is the actual object of the project.

Require substantial density before intervention.

Do **not** select examples after looking for steerability.

## Mechanism test: causal access, not generic steering

The first mechanism experiment should be as local as possible.

Candidate design:

1. select layer/token using validation only from the seed probe curve;
2. identify matched opposite-ranking donor examples;
3. perform counterfactual activation patching or low-rank interchange at the ranking-relevant state;
4. measure change in the logit difference between the two verbal answer choices;
5. evaluate on a locked test set.

The strongest causal result would be:

```text
baseline hidden state encodes correct ordering
baseline generation is wrong
→ replacing / moving only the ranking state toward the correct counterfactual state
→ generated ranking becomes correct
```

This would establish causal availability of latent magnitude information to generation.

A clean null is also interesting:

```text
ranking is highly linearly decodable
BUT direct causal intervention on that representation does not affect the decision
```

That would be strong evidence that “decodable knowledge” is not necessarily on the computation used by generation.

## Required intervention hygiene

Because recent steering audits show strong measurement confounds, do not use arbitrary raw coefficients.

Freeze:

- validation-selected layer/token;
- residual-norm-normalized intervention strength;
- held-out operating point;
- random direction control;
- shuffled-label / label-reversed control;
- matched-norm control.

Do not scan the test set for a successful layer × strength pair.

## Why this project is likely to survive

It removes several uncertainties that killed earlier candidates:

```text
Does the phenomenon exist?          YES, seed paper
Does it exist in an open model?     YES, 7B–8B models
Is the dataset public?              YES
Are labels exact?                   YES
Is reproduction code public?        YES
Is the next question explicit?      YES, seed limitation
Can we run the mechanism locally?   YES
Does a null mean something?         YES
```

The only major scientific risk left is whether the decodable ranking state is actually causally involved in the output. That is an acceptable research risk because it is the **question itself**, not a prerequisite we forgot to establish.

## Full-paper route if G0 is positive

Keep the scientific question fixed and expand only along natural axes:

1. Qwen3-8B discovery;
2. locked replication on 2–3 seed model families;
3. integer↔scientific and decimal↔scientific settings;
4. direct magnitude state vs pairwise-ranking state;
5. causal intervention;
6. minimal access-aware readout/adapter or inference correction.

This can reach ACL/EMNLP scale without inventing another benchmark.

**Status: `SURVIVAL_TOP / CODE_NEXT`**

# 4. SURVIVAL TOP 2 — Where Does the Einstellung Effect Arise?

## Seed / artifacts

ACL 2026 MedEinst:

- paper: https://aclanthology.org/2026.acl-long.1847/
- repo: https://github.com/zhui711/MedEinst
- dataset: https://huggingface.co/datasets/zhui711/MedEinst

Released benchmark:

- 5,383 counterfactual test pairs;
- 49 diseases;
- control vs trap case for the same diagnostic neighborhood;
- exact ground-truth diagnosis.

The paper reports large Bias Trap Rates across many models, including open Qwen-family models, so the project is not betting on whether Einstellung behavior exists at all.

## Why feasibility is high

The pair structure gives an unusually clean experimental unit:

```text
control narrative → diagnosis A
minimal decisive counterfactual change
trap narrative → diagnosis B
```

The critical subset can be defined automatically:

```text
control prediction = A
trap prediction = A   # fixation
while trap gold = B
```

No expert judge is required to define fixation.

## What is not as clean as numeracy

The official GitHub repository currently does **not** release the full ECR-Agent implementation; it mainly links the dataset and says the full agent code is forthcoming.

Therefore we must implement our own inference/scoring pipeline.

Also, MedEinst already analyzes generated reasoning into blindness / underthinking / overthinking-style failure categories. We cannot claim novelty from merely observing that a model verbally mentions the changed evidence and still gets the diagnosis wrong.

Our contribution must be the internal causal computation.

## Safer G-1 than free generation

Do not begin with medical free-text answer normalization.

For every pair, use the two known diagnoses:

```text
y_control = diagnosis A
y_trap    = diagnosis B
```

Measure forced candidate log-probabilities or a fixed two-choice prompt.

This produces a direct layer-independent behavioral margin:

```text
D = log P(y_trap | narrative) - log P(y_control | narrative)
```

The counterfactual should flip the sign of `D`.

G-1 requires a substantial number of:

```text
D_control < 0 correctly favoring A
D_trap    < 0 still favoring A despite gold B
```

(or equivalent sign convention).

## Mechanism question

> **Does decisive counterevidence fail to enter the representation, or does it enter but fail to update the diagnostic state?**

The paired narrative lets us track:

```text
changed evidence tokens
→ evidence representation
→ diagnosis margin across layers
```

A clean approach is to compute a layerwise diagnostic preference readout on the two gold diagnosis strings, then intervene only around the counterfactually changed evidence and the later decision token.

## Major implementation risk

The released dataset does not obviously expose an expert-annotated span that says “this exact token span is the decisive discriminative feature.”

The control/trap pair can be diffed automatically, but if many pairs involve broad rewriting rather than a narrow structured change, token-level patching becomes much less clean.

This is the first thing to audit before building hidden-state code.

Kill/downgrade if the paired changes are too diffuse for a stable intervention unit.

## Why still #2

Even if token localization is imperfect, the **pair itself** remains a clean counterfactual unit and the behavioral fixation phenomenon is already strong.

Unlike many archived topics, we are not searching for rare natural crossover.

The main unknown is where fixation lives computationally, which is a legitimate research uncertainty.

**Status: `SURVIVAL_TOP / SECOND`**

# 5. RUN G0 NOW — Progressive Quiz Bowl reversal

## Why literature search should stop temporarily

This candidate is now so cheap to falsify that further theorizing is wasteful.

Released resource:

- progressive questions: `mgor/protobowl-11-13`;
- agent responses: `mgor/protobowl-11-13-agent-responses`;
- roughly 304k response rows.

The only prerequisite that matters is:

> **Are clean correct→wrong reversals actually common?**

## Immediate offline screen

For each `agent/config × original_question`:

1. parse clue index from the progressive question id;
2. sort clue states;
3. construct correctness trajectory;
4. count:
   - `0→1`;
   - `1→1`;
   - `1→0`;
   - `1→0→1` recoveries;
5. separately count questions that ever reverse after first becoming correct.

Audit missing clue states and parser artifacts.

## Hard decision

If `1→0` is rare after cleaning, archive immediately.

Do **not** rescue by adding newly generated clues, choosing a special model, or redefining reversal as a confidence drop.

If the density is high, then and only then reproduce on one accessible open model and ask whether the previous correct answer remains internally represented after the reversal-inducing clue.

**Status: `RUN_G0_NOW`**

# 6. Round-03 #1 is downgraded — fact mutability → source routing

This is the clearest example of why feasibility must include **scientific identifiability**, not only engineering.

## Engineering audit: excellent

The official `knowledge-conflicts-mutability` repository contains:

- full mutable/stable CSVs;
- dataset generation scripts;
- model inference code;
- prompt files;
- stratification/evaluation code.

So this is easy to run.

## Identification audit: concerning

The dataset construction explicitly defines different relation families:

```text
mutable properties:
  position held
  sports team
  employer
  headquarters location
  ...

stable properties:
  place of birth
  date of birth
  citizenship
  religion
  ...
```

Therefore a linear `mutable vs stable` readout can trivially exploit **relation semantics**.

It does not establish a runtime abstract mutability state.

This is not a small nuisance. It attacks the exact mechanism claim.

To repair it, we would need same-relation changes, relation-matched controls, lexical controls, or another mutability construction. The gate starts becoming:

```text
mutability effect
conditional on relation identity
conditional on lexical form
conditional on conflict type
...
```

That is the complexity smell we explicitly promised to stop pursuing.

## Collision pressure

The generic mechanism space is also busy:

- context-vs-parametric-memory conflict analysis;
- residual-stream source-reliance analysis;
- activation steering for contextual faithfulness;
- task-dependent knowledge conflict studies.

Thus even a successful generic source-selection intervention would not provide enough novelty.

### Decision

`DOWNGRADE / DO NOT REGISTER IN CURRENT FORM`

This candidate can only return if a naturally matched mutability object appears that removes relation identity without bespoke controls.

# 7. New Round-04 lead: TruthTrap — attractive artifacts, but do not overpromote

## Seed

EACL 2026 TruthTrap studies **factually correct but strategically misleading information**.

Resources:

- 1,000 curated items per language (English/Farsi);
- question + correct explanation + true misleading hint + four MCQ options;
- public CSV and evaluation notebook:
  https://github.com/Mamin78/truthtrap_with_code

The paper reports a large behavioral effect: adding a true but misleading hint substantially lowers QA accuracy and strongly increases hint-aligned choices.

A particularly interesting reported dissociation is that models can judge a hint as false/uncertain in an isolated factuality task while that same content still influences the QA decision.

## Tempting question

> **Can information that the model explicitly rejects still causally steer its answer?**

This sounds excellent for mechanism work.

## Why it is only WATCH

The two observations happen under different tasks:

```text
isolated factuality classification
vs.
question answering with the hint embedded
```

So the gap does not cleanly imply:

```text
stable internal belief = reject hint
BUT action uses rejected belief
```

The model may simply represent the statement differently because the task/context changed.

To turn this into a causal “belief vs influence” claim, we may need multiple controls for prompt/task equivalence — exactly the kind of expanding identification problem that has killed earlier topics.

The dataset is excellent; the scientific mapping is not yet clean enough.

**Status: `WATCH / ARTIFACT-RICH, IDENTIFICATION-RISK`**

# 8. New leads inspected but not promoted

## A. Harmful Factuality / source-unfaithful correction

Recent work shows models sometimes overwrite deliberately perturbed source facts with parametric truths, yielding outputs that are factually correct but unfaithful to the source.

The labels and scoring can be automated, but generic parametric-vs-contextual knowledge mechanisms are now crowded, including activation-based interventions for contextual faithfulness.

**Decision:** `KILL_AS_PRIMARY_TOPIC / COLLISION`

## B. ReflecTool self-reflection gap

The critique→self-reflection gap is real and the benchmark is released, but identifying a genuine **ownership/self-attribution mechanism** requires holding dialogue content/history constant while changing self-vs-other provenance.

That manipulation risks becoming prompt-artificial and control-heavy.

**Decision:** `DEPRIORITIZE`

## C. Confidence-leap / reasoning-transition mechanism

Good open-model traces and strong behavior, but recent 2025–2026 literature already performs correctness prediction, activation steering, and reasoning-trajectory intervention.

**Decision:** `DEPRIORITIZE_CROWDED`

## D. Generic context-memory conflict

ACL 2026 work such as *Task Matters* further expands controlled context-memory conflict analysis across knowledge requirements.

A generic “where does context beat memory?” project no longer has enough novelty.

**Decision:** `KILL_GENERIC_VERSION`

## E. MediEval / medical counterfactual grounding

High-quality paired counterfactual object and an ACL 2026 Outstanding Paper, but the paper already introduces a mitigation method and the medical counterfactual-evidence area now overlaps substantially with MedEinst and other recent work.

MedEinst has the cleaner old-science anchor and larger pair structure for our mechanism question.

**Decision:** `DO NOT ADD ANOTHER MEDICAL COUNTERFACTUAL TOPIC`

# 9. Important methodological correction for all mechanism candidates

A very recent 2026 audit, **When Is a Steerable Concept Representation Real? Measurement Confounds in a Cross-Family Audit of Neuroscience Parallels in LLMs**, is directly relevant to our project-selection logic.

It shows that apparent steering trends can depend on:

- raw activation units;
- residual-stream norm;
- chosen layer;
- steering strength;
- output readout;
- operating-point selection.

Therefore future candidate validation must distinguish:

```text
decodability
causal relevance
steerability under calibrated intervention
```

These are not interchangeable.

For any mechanism topic, we should standardize:

1. disjoint train/validation/test;
2. validation-only selection of layer/strength;
3. residual-norm-comparable steering;
4. random/shuffled concept nulls;
5. one locked test evaluation;
6. preferably counterfactual patching before free-form steering when a natural pair exists.

This makes the experiment **more** precise without multiplying semantic controls around the construct.

# 12. Round-04 search rule going forward

New leads must preferentially satisfy all of:

```text
1. published in / aligned with ACL, NAACL, EMNLP, EACL, TACL
2. nontrivial phenomenon already shown
3. open-weight model among the reported systems
4. released dataset
5. released prompts/scoring/code
6. automatic or existing gold labels
7. meaningful critical-cell density visible or cheaply measurable
8. exact mechanism question not already answered
9. one-clean-contrast intervention possible
10. no large API / new annotation prerequisite
```

A paper that gives us all of 1–6 is much more valuable than a spectacular anomaly reported only on inaccessible frontier APIs.

# Round-04 conclusion

The most important outcome of this round is not another large topic pool.

It is a change in what counts as a promising topic.

The current best candidate is now **numerical representation vs causal access**, because almost every prerequisite has already been paid for by the seed paper:

```text
phenomenon exists
open model exists
exact data exists
code exists
ground truth exists
behavior/representation gap exists
```

We only need to answer the new question:

> **Is the correct latent numerical state actually causally available to generation, and if so, where does access fail?**

MedEinst remains a strong second candidate because its paired counterfactual design makes the fixation phenomenon unusually concrete.

Quiz Bowl remains worth exactly one immediate offline screen; it should either become real quickly or disappear quickly.

Fact mutability is downgraded despite excellent code because its scientific mechanism contrast is not clean enough. This is intentional: **engineering feasibility is necessary, but scientific identifiability is part of feasibility too.**

The next milestone should therefore not be “Round 05 found more ideas.” It should be:

> **at least one of the top three has passed an exact prerequisite reproduction on the artifacts we will actually use.**
