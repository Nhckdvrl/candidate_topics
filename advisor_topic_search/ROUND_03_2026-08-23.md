# Advisor Topic Search — Round 03 (2026-08-23)

## Objective

This round re-runs the topic pool under the revised README rather than inheriting Round 02 rankings.

The binding profile is now:

```text
ACL / NAACL / EMNLP-scale scientific question
+ clear external seed or old scientific problem
+ little/no large paid API dependence
+ little/no new large-scale annotation
+ existing labels/data/open checkpoints when possible
+ strong preference for mechanism-ready phenomena because local GPU is abundant
```

The key correction from Round 02 is that we are **not compute-constrained in the same way that we are cash/annotation constrained**. Therefore a nearly-free behavioral analysis is not automatically superior to a GPU-heavy mechanism project. If a clean behavioral phenomenon already exists, we should actively value questions that let us use open models for hidden-state analysis and causal intervention.

At the same time:

> `mechanistic analysis != novelty`.

If a recent paper has already done the same neuron/probe/patch/steer question, adding another model or dataset is not enough.

A useful positive calibration example from ACL 2026 is the paper on **content effects in logical reasoning**: it takes an old cognitive-science distinction (logical validity vs. plausibility), establishes a behavioral content effect in LLMs, identifies separable internal directions, connects geometry to behavior, and performs causal cross-steering.

This is close to the *shape* we want:

```text
old / externally meaningful scientific distinction
→ behavioral dissociation
→ internal representation
→ causal-use test
→ mitigation / broader implication
```

We should copy this *research shape*, not the topic itself.

# 3. TOP 1 — Do LLMs Know Which Facts Can Change but Fail to Route That Signal into Source Selection?

## Venue-scale headline

> **LLMs know which facts can change, but their knowledge-conflict decision circuit fails to use that knowledge.**

## Seed chain

### Seed A — MuLan (NAACL 2024 Short)

Fierro et al., **“MuLan: A Study of Fact Mutability in Language Models.”**

https://aclanthology.org/2024.naacl-short.67/

The paper establishes that mutable vs. immutable facts differ in model confidence, representations, and update behavior.

So the premise

> `fact mutability is represented`

already has external support.

### Seed B — When Facts Change (Findings ACL 2026)

Wallat et al., **“When Facts Change: Temporal Knowledge Conflict Resolution in LLMs.”**

https://aclanthology.org/2026.findings-acl.103/

The paper releases **WIKIRECENTCHANGES**, containing stable and recently updated facts from Wikidata, and reports a striking scale-dependent disconnect:

- models reason differently about facts that actually changed vs. stable facts;
- larger models can detect the temporal conflict;
- explicit prompting makes mutability reasoning more visible;
- but the distinction rarely reaches the final factual prediction;
- larger models can therefore **detect the issue yet fail to act on the mutability judgment**.

The paper explicitly frames the need to better connect temporal awareness to decision-making.

## Natural next question

> **Is the missing computation not mutability recognition, but routing the already-available mutability signal into the context-vs-parametric-memory source selector?**

This is one step beyond the seed:

```text
Seed: mutability judgment is behaviorally/verbalized available but underused
Us: is mutability represented at the conflict decision point, and is failure specifically causal non-use of that representation?
```

## Why this is a real scientific question

When two knowledge sources disagree, an intelligent system should not have a fixed preference for context or memory. A naturally relevant variable is whether the fact is the kind of fact that changes.

The surprising part is already published: models can notice changeability without using it.

The question is therefore not invented by a probe.

## Exact collision audit

Nearby work already studies:

- context-vs-parametric-memory conflict;
- generic context/source preference;
- prompting models to rely on one source;
- representation steering for generic source selection;
- temporal robustness and evolving knowledge.

Those generic versions are crowded and **must not be our contribution**.

Current search did **not** find a paper that directly performs the following causal chain on natural temporal conflicts:

```text
fact-mutability representation
→ source-selection decision
→ causal intervention specifically on mutability
```

This remains a collision-sensitive claim and must be re-searched before registration, especially against 2026 source-selection steering papers.

## Existing resources

- WIKIRECENTCHANGES benchmark and public code/data announced by the seed paper;
- Wikidata-derived stable/updated labels;
- MuLan resource as an independent mutability representation source;
- open-weight Qwen / Llama / Gemma-class models for local hidden-state access.

## G0 — same-model phenomenon + representation prerequisite

Do **not** begin with an SAE.

Pick 1–2 open models that are large enough to reproduce the seed’s “detect but fail to act” regime.

For each conflict item, define:

```text
M = mutability judgment / temporal-conflict recognition is correct
Y = final source choice is correct
```

The critical cell is:

```text
M = correct
Y = wrong
```

Require useful instance-level density, not only an aggregate difference.

Then test whether a frozen linear readout of mutability remains strong at the decision-relevant token/layers on these `M-correct / Y-wrong` cases.

### G0 kill line

Kill if any of the following holds:

1. available open models do not reproduce a sizeable detect-but-not-act cell;
2. mutability is not robustly decodable in the same model/instances where behavior fails;
3. the effect only appears after searching many layers/prompts/models;
4. stable vs. mutable conditions have no usable common support after simple relation-level matching.

## Mechanism phase

If G0 passes, estimate a mutability direction/subspace on a disjoint training split and intervene during conflict resolution:

- patch mutable→stable and stable→mutable representations;
- steer along the mutability direction while holding the evidence text fixed;
- measure whether the model switches context-vs-memory source choice;
- compare with random-direction and generic context-reliance controls.

The target is not merely “probe accuracy.” It is:

> **changing the mutability state changes which knowledge source the model trusts.**

## Method opening

A positive result directly motivates a **conditional source router** or training objective that makes conflict resolution depend on fact mutability rather than a global context/memory preference.

## Resource gate

```text
Paid API requirement for G0: 0
New annotation requirement for G0: 0
Open-weight model availability: yes
Local compute: moderate/high inference + hidden-state extraction + intervention
Storage: manageable if activations are restricted to selected layers/tokens after G0
Mechanism-ready: excellent
```

**Status: `TOP_POOL / HIGHEST_PRIORITY`**

# 4. TOP 2 — Where Does the Einstellung Effect Live? Evidence Encoding vs. Diagnostic Attractor

## Venue-scale headline

> **LLMs can read the evidence that should change a diagnosis, yet remain trapped by the diagnosis suggested by the typical case.**

This exact stronger headline is a hypothesis, not assumed fact; G0 must decide whether it is true.

## Old scientific question

The **Einstellung effect** is a classic cognitive phenomenon: prior experience or a familiar solution schema can create a mental set that blocks a better solution when the situation changes.

This is exactly the kind of old question the advisor values when the LLM setting gives a new handle.

## Seed — MedEinst (ACL 2026 Long)

Chen et al., **“MedEinst: Benchmarking the Einstellung Effect in Medical LLMs through Counterfactual Differential Diagnosis.”**

https://aclanthology.org/2026.acl-long.1847/

The paper constructs **5,383 paired counterfactual test cases across 49 diseases**.

Each pair contains:

```text
control case: typical presentation → diagnosis A
trap case: minimally changed discriminative evidence → correct diagnosis B
```

The trap remains statistically similar to the control, but the correct diagnosis flips.

The official dataset is released on Hugging Face and contains 10,766 test rows plus a much larger training/reference split:

https://huggingface.co/datasets/zhui711/MedEinst

The seed reports high control accuracy but severe Bias Trap Rate across frontier models.

It also performs textual reasoning failure analysis, but does not establish a hidden-state causal mechanism for the fixation.

## Natural next question

The clean old cognitive question becomes computational:

> **When the discriminative evidence changes, does the model fail because the new evidence never becomes represented strongly enough, or because an already-formed diagnostic state resists being overwritten?**

This is much more specific than “why is medical reasoning biased?”

## Why this is unusually well identified

The paired counterfactual design is extremely useful for mechanism work:

```text
same disease neighborhood
same narrative style
minimal discriminative change
control correct
trap wrong
```

The critical comparison already exists naturally in the released benchmark; we do not need to invent a new ontology.

## Collision audit

There is earlier/parallel work on the medical Einstellung effect and medical bias, and MedEinst itself proposes an evidence-centric agent mitigation.

There is also generic medical activation-patching work on demographic representations.

Current exact search did **not** find a study that uses the MedEinst paired counterfactuals to causally distinguish:

```text
evidence-not-encoded
vs.
evidence-encoded-but-diagnostic-state-not-updated
```

This is the novelty claim to protect.

## G0 — is the “encoded but ignored” cell real?

Use one strong open model first (e.g. Qwen3-class) and freeze a sizeable subset of pairs where:

```text
control = correct
trap = wrong
```

For each pair, leverage the known changed discriminative evidence.

Test two simple readouts across the narrative:

1. target evidence / discriminative-feature identity;
2. control-vs-trap diagnostic target.

The key prerequisite is a substantial set of trap errors where the changed evidence is strongly decodable but the final diagnosis remains the old/control diagnosis.

### G0 kill line

Kill if trap failures are mostly cases where the model never represents the changed discriminative evidence, or if the putative diagnosis-state/evidence-state separation only appears after broad layer fishing.

## Mechanism phase

The strongest causal experiment would use the paired nature directly:

- patch only the discriminative-evidence representation from trap→control or control→trap;
- separately patch later diagnostic-state representations;
- ask where the diagnosis flips;
- localize whether evidence is integrated and then overwritten/ignored, or never integrated in the first place.

A useful causal signature would be:

```text
evidence representation changes appropriately in trap cases
BUT
later diagnostic state remains control-like
AND
patching the relevant integration path rescues the trap diagnosis
```

## Method opening

If fixation occurs at a specific evidence-integration stage, design an evidence-gated update or contrastive training objective that forces decisive counterevidence to update the diagnostic state.

This could generalize beyond medicine to any domain where a strong prior must be revised by a small decisive cue.

## Resource gate

```text
Paid API requirement for G0: 0
New annotation requirement for G0: 0
Dataset: fully released
Open models: yes
Local compute: moderate/high hidden-state + patching workload
Expert annotation: not needed for core labels because paired diagnosis labels already exist
Mechanism-ready: excellent
```

**Status: `TOP_POOL / HIGHEST_PRIORITY`**

# 5. TOP 3 — Can More True Evidence Make a Model Abandon a Correct Answer?

## Venue-scale headline

> **A language model can reach the right answer, receive more true evidence for that same answer, and become wrong.**

## Seed / resource

Gor et al., EMNLP 2024, **CAIMIRA / “Do Great Minds Think Alike?”**

https://aclanthology.org/2024.emnlp-main.1201/

The authors release progressive Quiz Bowl questions and about **304k AI-agent responses** across clue states:

- https://huggingface.co/datasets/mgor/protobowl-11-13
- https://huggingface.co/datasets/mgor/protobowl-11-13-agent-responses

Quiz Bowl naturally reveals additional true clues while the answer remains fixed.

## Natural next question

> **After a model first becomes correct, how often does an additional true clue cause a correct→wrong reversal?**

This is an old evidence-integration / belief-revision question in a naturally incremental NLP object.

## Why it survives the Round-03 re-audit

Search finds broad work on:

- more context hurting models;
- incremental QA;
- calibration / buzzing;
- CAIMIRA human-AI ability comparison.

But current search still did not find an exact paper centered on **instance-level correct→wrong reversals under naturally ordered, answer-preserving Quiz Bowl clues**.

This distinction is important: generic “more context hurts” mixes truncation, distractors, irrelevant retrieval, and changed task conditions. Here the new text is another true clue from the same human-written question.

## Important human-data caveat

CAIMIRA’s processed human trajectories impose/backfill monotonic correctness under an assumption that later clues are easier. Therefore:

> **Do not use the processed human trajectory as evidence that humans are monotonic while LLMs are not.**

The first project-level claim should be model-only unless raw human buzz behavior supports an unbiased comparison.

## G0 — almost free

Using the released response table only:

1. reconstruct `model × question × clue-index` correctness trajectories;
2. count clean `0→1`, `1→1`, `1→0`, and recovery transitions;
3. inspect answer identity changes at `1→0` boundaries;
4. remove parser/duplicate/missing-state artifacts;
5. freeze a minimum reversal-density threshold before explanatory work.

### Kill line

Kill if clean reversals are sparse or mostly output-normalization artifacts.

## Mechanism phase

If the released logs show a strong phenomenon, re-run a small number of open models locally and capture activations immediately before and after reversal-inducing clues.

Ask:

> **Does the previous correct answer representation disappear, or remain present while a new clue changes the readout/selection dynamics?**

Potential causal tests:

- patch the pre-reversal answer state into the post-clue trajectory;
- isolate the new clue’s contribution by attention/path intervention;
- compare reversal-causing clues to matched non-reversal clues of similar position/informativeness.

## Method opening

- evidence integration with hysteresis / commitment thresholds;
- confidence-aware stopping;
- update rules that require sufficient contradictory evidence before overwriting a high-confidence answer;
- incremental QA training that penalizes unsupported answer reversal.

## Resource gate

```text
Paid API G0: 0
New annotation G0: 0
Released responses: ~304k
G0 GPU: ~0
Mechanism phase GPU: moderate/high
Mechanism-ready after G0: strong
```

**Status: `TOP_POOL`**

# 6. HIGH — When Models Know Numerical Magnitude, Why Can’t Generation Use It?

## Seed

Yuchi, Du, Eisner, EACL 2026 Short, **“LLMs Know More About Numbers than They Can Say.”**

https://arxiv.org/abs/2602.07812

The paper finds:

- numerical magnitude is linearly recoverable from hidden states;
- pairwise ranking is >90% decodable;
- explicit mixed-notation ranking is only ~50–70%;
- adding probe loss during finetuning improves verbal performance by another 3.22%.

## Round-03 sharpening

The developmental version (“when does representation emerge before behavior?”) is less interesting now.

The stronger question is:

> **Where in the computation does an already-accurate magnitude/ranking representation fail to become the generated comparison answer?**

## Novelty risk

The seed already shows that improving the internal representation during training improves verbal behavior, so we cannot claim simply that representation quality matters.

What appears still open is **localized causal access / routing**:

```text
correct latent ranking
+ wrong verbal answer
→ which transformation/readout loses or ignores the correct ranking?
```

Recent work on ordinal representation geometry and activation interventions makes collision search important.

## Resource fit

Excellent: open models, public probing data, synthetic exact labels, local GPU mechanism work, no paid API/annotation.

**Status: `HIGH / DEEP_AUDIT`**

# 7. HIGH — Does a Model Compute the Possible Score Range but Still Misjudge Determinability?

## Seed

Watanabe et al., ACL 2026 Industry, **ClinDet-Bench**:

https://aclanthology.org/2026.acl-industry.47/

Repository:

https://github.com/yusukewatanabe1208/ClinDet_Benchmark

The repository releases:

- 94 clinical scenarios;
- 16 scoring-system explanation tasks;
- raw outputs from 8 models × 3 prompting conditions;
- benchmark code.

The seed finds premature conclusions and excessive abstention under incomplete information even when models explain the scoring knowledge correctly and perform well under complete information.

## Natural next question

For many scoring systems, determinability can be formalized through the feasible range of scores under missing variables.

So ask:

> **Does failure happen because the model cannot compute the feasible range, or because it computes the right range but fails to map it to the determinability decision?**

This gives an unusually clean computational decomposition:

```text
missing-variable hypotheses
→ [S_min, S_max]
→ compare range to decision threshold
→ determinable / undeterminable
```

## Why not TOP yet

- only 94 primary scenarios are released;
- we must confirm the scoring systems permit sufficiently automatic extraction of intermediate gold ranges;
- scaling by generating new exact cases is possible but should not become a bespoke benchmark-construction project.

## Mechanism opening

If correct range computation and wrong determinability coexist at useful density, this becomes another clean `internal computation available → decision readout fails` case suitable for causal intervention.

**Status: `HIGH / DEEP_AUDIT`**

# 8. WATCH — Why Are Models Better Critics of Others Than of Their Own Tool Errors?

## Seed

Liu et al., Findings ACL 2026, **“Do LLMs Catch Their Own Mistakes? A Comprehensive Benchmark for Reflective Tool Use LLMs.”**

https://aclanthology.org/2026.findings-acl.86/

ReflecTool-Bench has 968 annotated multi-turn tool-use dialogues across 10 domains and 88 APIs. The paper reports:

- models can diagnose errors in third-party dialogue critique;
- performance drops sharply in self-reflection;
- assistant-originated errors are particularly hard;
- recognition does not reliably become actionable repair.

## Potential one-step

> **Is there an ownership/self-attribution effect in error monitoring, or are critique and self-reflection simply different tasks?**

A powerful design would need **identical error content with only ownership/history manipulated**, otherwise the mechanism is not identifiable.

## Why only WATCH

The matched ownership manipulation may become artificial and prompt-sensitive. If it needs many controls to argue that “self-ownership” is the cause, kill under the complexity-smell rule.

**Status: `WATCH / HIGH`**

# 9. WATCH — Is a Confidence Leap a Causal Reasoning-State Transition?

EACL 2026 **Confidence Leaps in LLM Reasoning** reports sudden jumps in answer probability, successful early stopping, and cross-model transfer of the reasoning chunks associated with leaps.

The tempting question is whether the leap marks a causally necessary state transition rather than merely a readout consequence.

This is attractive for local activation analysis, but confidence/self-correction/latent-correctness work in 2025–2026 is already crowded with causal studies. Do not promote unless exact collision search reveals a genuinely distinct computational claim.

**Status: `WATCH / CROWDED`**

# 10. Re-audit: candidates downgraded or killed

## K1. None-of-the-Above local-vs-global rejection

Round 02 rank: `TOP_POOL #1`

### Collision discovered

COLING 2025 **MCQA+ / “LLMs May Perform MCQA by Selecting the Least Incorrect Option”** already decomposes MCQA into closely related settings including:

- T/F judgment of the correct option;
- T/F judgment of each incorrect option;
- removing the correct answer and introducing None-of-the-Above;
- no-correct-option settings.

Therefore our proposed

> “all options individually rejected, but joint NA still fails”

is a stricter conditional statistic but not enough scientific distance from the existing experimental decomposition.

### Decision

`DOWNGRADE_COLLISION_RISK / LIKELY_KILL`

Do not rescue by saying “we condition on all four being correct.”

# Round-03 conclusion

The new resource standard changes the pool in a useful way.

The strongest candidates are no longer simply the cheapest behavioral analyses. The best current profile is:

```text
published dissociation / old scientific problem
+ existing paired or exact-label data
+ open model access
+ a cheap behavioral prerequisite gate
+ a genuinely unresolved causal-use question
+ GPU-heavy mechanism analysis after G0
```

Under that standard, the current top three are:

1. **fact mutability signal → source-selection routing**;
2. **Einstellung trap → evidence encoding vs diagnostic fixation**;
3. **progressive true evidence → correct-to-wrong reversal and overwrite mechanism**.

The previous NA candidate is no longer top after a closer collision audit. That is intentional: Round 03 should improve the pool, not preserve earlier rankings.
