# 1. When Is No Evidence Evidence?

## Mother question

When should a non-observation itself count as evidence against a hypothesis, and do LLMs reason about the observation process that determines that evidential force?

## Main-scale narrative

One-dimensional detectability calibration alone would be too small. The full paper unifies:

1. detectability / false-negative rate;
2. search effort vs actual coverage/sensitivity;
3. repeated null results with independent vs overlapping coverage;
4. downstream continue-search / abstain / conclude-absence decisions.

## Unique novelty package

Existing RAG/abstention work studies missing evidence, answerability, sufficiency, and search stopping. The proposed story is specifically **observation-model-sensitive negative evidence reasoning**: `not found` has no fixed epistemic meaning without `P(observe evidence | H)`.

## Method runway

**Observation-Model-Aware Search / Belief Controller** that tracks coverage, sensitivity, overlap, and false-negative rate, converts null observations into likelihood contributions, and controls belief updates and stopping.

## G0

Synthetic scenarios with identical content/prior and identical `not found` outcome while varying only expected detectability. First test ordinal monotonicity, then overlap-aware accumulation.

## Verdict

`STRONG_KEEP`

# 2. Controls Are Tests of Assumptions

## Mother question

Can an LLM scientific reasoner determine what assumption a negative/positive/placebo control tests, whether a proposed control is valid, and what a pass/fail result does to the main claim?

## Main-scale narrative

1. control selection for a stated causal threat;
2. control validity;
3. interpretation of pass/fail outcomes;
4. generation and transfer to unseen study descriptions.

Factorization:

```text
no direct treatment effect
× shared relevant bias/confounding pathway
× sufficient sensitivity to expose violation
```

## Unique novelty package

AI-scientist work already evaluates experiment generation and falsification, and recent work uses negative controls inside evaluation pipelines. The proposed narrative is different: **the semantics and causal validity conditions of controls themselves**.

## Method runway

**Control-Aware Scientific Critic / Experiment Designer** that explicitly binds each control to the threatened assumption, invariance requirement, shared bias mechanism, and expected diagnostic power.

## G0

Programmatic causal graphs + natural-language studies with one valid control and several exact invalid controls (direct treatment effect, no shared confounding, insufficient sensitivity).

## Verdict

`STRONG_KEEP`

# 3. Annotation Policy Is Part of the Task

## Working title

**Annotation Policy Is Part of the Task: Separating Domain Shift from Task-Definition Shift in NLP**

## Mother question

When two NLP datasets are said to represent the same task, how much cross-dataset failure comes from differences in the input domain, and how much comes from differences in how the task itself was operationalized by annotation guidelines and policies?

## External construct

Annotation policy is part of the data-generating process. The same underlying text can legitimately receive different labels under different operational definitions, span rules, scope decisions, ambiguity policies, cultural conventions, or label taxonomies.

This issue exists independently of LLMs and has long affected NLI, offensive-language detection, NER, event/coreference annotation, sentiment, framing, and many other NLP tasks.

## Closest collisions

- task harmonization work aligns schemas/formats across datasets;
- task-specific studies have shown cross-corpus drops caused by annotation mismatch rather than domain shift;
- AlignGuide / guideline-data co-reconciliation directly targets cross-dataset annotation conflicts;
- guideline-conditioned classification is an active area.

Therefore the paper cannot claim merely that guidelines matter or propose generic guideline reconciliation.

## Unique novelty package

The distinct Main-scale narrative is:

> **Cross-dataset transfer should decompose into domain shift and task-definition shift. In the LLM era, annotation policy can become an explicit, recoverable task variable rather than an invisible property baked into gold labels.**

A full paper should contain:

1. **shift decomposition:** content/domain shift vs annotation-policy shift under matched examples;
2. **policy recovery:** infer the operative annotation policy from guideline text + small example sets;
3. **policy-conditioned prediction:** the same instance may require different outputs under different valid policies;
4. **cross-dataset harmonization:** translate predictions/labels across policies without pretending one dataset is the unique truth;
5. **boundary condition:** distinguish genuinely semantic disagreement from policy-induced disagreement.

This is broader than one offensive-language case study and different from purely reconciling schemas.

## Expected headline findings

Possible abstract-level findings:

1. a substantial portion of apparent cross-dataset generalization failure is attributable to annotation-policy shift rather than input-domain shift;
2. LLMs can often verbalize policy differences yet still default to a dataset-specific learned convention when making predictions;
3. policy-conditioned inference improves transfer without forcing heterogeneous datasets into one canonical label definition;
4. some datasets are genuinely incompatible because the annotation policies encode different constructs rather than noisy variants of one task.

## Method runway

**Policy-Conditioned NLP / Annotation-Policy Harmonization**

Possible method family:

```text
instance
+ explicit/inferred annotation policy
+ target label ontology
→ policy-conditioned prediction
```

and for cross-dataset training:

```text
source labels + source policy
→ latent construct / policy-specific mapping
→ target-policy label
```

A method could jointly infer policy differences, condition the classifier on policy, and preserve multiple legitimate task definitions instead of collapsing them into a single canonical gold standard.

## Why method follows

If the study shows that domain adaptation is solving the wrong problem because the target task definition changed, the remedy is policy-aware prediction/harmonization, not more domain-invariant representation learning.

## G0

Use existing paired/cross-corpus examples from 2–3 tasks with documented guideline differences. First construct matched cases where input semantics are held fixed but policy-derived labels differ. Test whether models produce policy-consistent labels when policies are switched, then separate policy shift from content/domain shift.

## Risk

Collision is real. AlignGuide and task-specific annotation-shift studies occupy part of the space. The paper survives only if it stays centered on the **domain-shift vs task-definition-shift decomposition + policy-conditioned task formulation**, not generic guideline reconciliation.

## Verdict

`NEW_STRONG_KEEP / MAIN_SCALE / NLP_NATIVE / COLLISION_MEDIUM / METHOD_RUNWAY_VERY_STRONG`

# 4. Missingness Is Data

## Mother question

Does an LLM data-analysis agent understand that the process producing missing values changes which analyses, estimands, and conclusions are valid—even when the visible incomplete table is the same?

## Main-scale narrative

1. same visible missing table, different MCAR/MAR/MNAR mechanisms;
2. mechanism × analysis choice;
3. mechanism × target estimand;
4. identifiability boundary: point estimate vs bounds/sensitivity/ask-for-more-data.

## Unique novelty package

Recent LLM work primarily studies imputation or prediction under MCAR/MAR/MNAR. The proposed narrative is **inference and identifiability under missingness mechanisms**, not filling missing cells.

## Method runway

**Missingness-Mechanism-Aware Data Analysis Agent** that infers/receives a missingness graph, checks ignorability/recoverability, chooses the analysis family, and returns bounds/sensitivity/abstention when point identification is impossible.

## G0

Synthetic complete data with known truth and controlled missingness mechanisms; exact labels for which analysis is valid and whether the target is identifiable.

## Verdict

`STRONG_KEEP`

# 5. Same Study, Different Population

## Mother question

Given internally valid evidence from a source population, can an LLM determine whether and how the result transports to a different target population?

## Main-scale narrative

1. effect-modifier awareness;
2. irrelevant covariate shift vs true effect-modifier shift;
3. positivity/support violations;
4. multi-study synthesis for a specific target population;
5. explicit vs inferable vs missing transportability information.

## Unique novelty package

Current LLM evidence-synthesis systems mostly extract/aggregate studies or use surface eligibility/population similarity. The proposed question is about **causal transportability conditions**, not generic similarity or the model's own domain generalization.

## Method runway

**Transportability-Aware Evidence Synthesis Agent** that extracts candidate effect modifiers, represents source-target structural differences, checks support/positivity, reweights/standardizes when valid, and abstains/requests target data when transport is not identified.

## G0

Synthetic randomized studies with known heterogeneous treatment effects. Hold source-study result and population mismatch magnitude fixed while switching whether the shifted variable is irrelevant or a true effect modifier.

## Verdict

`STRONG_KEEP`
