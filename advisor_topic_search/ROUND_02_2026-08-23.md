# 3. TOP_POOL 1 — Can a Model Reject Every Option but Still Fail to Choose None-of-the-Above?

## Seed / external anchor

Tam et al., Findings of ACL 2025, **“None of the Above, Less of the Right: Parallel Patterns in Human and LLM Performance on Multi-Choice Questions Answering.”**

- ACL: https://aclanthology.org/2025.findings-acl.1031/
- arXiv: https://arxiv.org/abs/2503.01550

The paper modifies MMLU questions so that the original correct option is removed and `None of the Above` becomes correct. Across 28 LLMs, performance drops by roughly 30–50% when NA is the answer.

Importantly, the paper contains examples where the model demonstrates knowledge relevant to rejecting an option and nevertheless selects an invalid option in the NA version.

## What the seed already proves

The problem is not merely that NA examples are harder in the ordinary sense. There is a large, broad failure when the correct action requires rejecting the listed candidates and concluding that no candidate is valid.

## Natural next question forced by the result

The paper interprets the phenomenon as difficulty systematically evaluating and rejecting all options, but does not directly isolate the missing computation.

The clean next question is:

> **Can a model correctly reject A, B, C, and D when each is judged individually, yet still fail to choose `None of the Above` when exactly those same candidates are presented jointly?**

This separates:

```text
local candidate verification
        vs
set-level aggregation / meta-decision
```

without claiming a hidden mechanism first.

## Why this is not “of course”

If the model truly lacks the underlying knowledge, it should fail the individual rejection probes too.

If it rejects every candidate separately but nevertheless chooses one of them jointly, the failure is not simple ignorance. It is a compositional decision failure between information the model can express locally and the action it takes globally.

## Existing resources

- MMLU gold answers;
- the paper's deterministic NA construction / suitability protocol;
- WiCkeD provides another automatically constructed NA-style benchmark:
  https://aclanthology.org/2025.acl-short.94/
- many open-weight model families can be evaluated locally.

No new semantic annotation is required for the core G0.

## Cheapest decisive experiment

1. Use a frozen subset of NA-suitable MMLU items.
2. For every remaining wrong option, ask a binary candidate-verification question with the same stem: is this candidate a correct answer? Gold label = `No`.
3. Separately run the original joint NA question.
4. Define the critical cell:

```text
all remaining candidates individually rejected correctly
AND
joint NA question answered incorrectly
```

Primary quantities:

- density of this dissociation among NA failures;
- `P(joint fail | all local rejects correct)`;
- replication across 2–3 open model families.

No judge is needed.

## Kill line

Kill if the critical cell is rare, unstable, or disappears once the exact same deterministic question subset is used across models.

A useful first gate should require a substantial fraction of NA failures to survive after conditioning on perfect local rejection; otherwise the original paper's failure can be explained mostly by missing item-level knowledge.

## Collision audit

Closest work found:

- Tam et al. 2025: establishes the NA failure, but not the systematic local-vs-global decomposition.
- WiCkeD (ACL 2025): automatically creates harder NA-style benchmarks, but does not ask this dissociation question.
- recent absent-answer / humility benchmarks extend NA to medicine and multimodal tasks, but again mostly measure joint abstention.
- older QA work has used “separately judge then select” as an algorithmic idea, so **the contribution must not be sold as inventing independent candidate evaluation**. The novelty would be the modern-LLM dissociation itself and what it says about decision composition.

## Positive-result headline

> **LLMs can reject every available answer individually and still fail to conclude that none of them is correct.**

## Method / mechanism opening

A positive result immediately creates several nontrivial next steps:

- identify where local judgments fail to bind into a set-level decision;
- compare likelihood aggregation vs generated reasoning;
- causal intervention on candidate-verification states;
- decomposed verification/aggregation decoding;
- abstention methods that reuse local evidence rather than learning another global refusal token.

## Resource gate

```text
Paid API requirement for G0: none
New annotation requirement for G0: none
Local compute: low; inference only
Released-artifact-only G0: mostly yes
```

**Status:** `TOP_POOL`

# 4. TOP_POOL 2 — Can More True Clues Make a Model Lose a Correct Answer?

## Seed / external anchor

CAIMIRA / Gor et al., **“Do Great Minds Think Alike? Investigating Human-AI Complementarity in Question Answering”** (EMNLP 2024) creates a progressive Quiz Bowl setting and releases both questions and large response logs.

Resources:

- progressive-clue dataset: https://huggingface.co/datasets/mgor/protobowl-11-13
- released response records: https://huggingface.co/datasets/mgor/protobowl-11-13-agent-responses

The public collection contains about 3.8k progressive-clue examples and about 304k agent-response records.

## What the seed already gives us

A Quiz Bowl question is naturally revealed from earlier/less specific clues toward later/more informative clues. The final answer stays fixed. Each prefix therefore gives a real evidence-acquisition trajectory rather than a synthetic context-length perturbation.

## Natural next question

> **If the model has already reached the correct answer, can adding another true clue make it switch to a wrong answer?**

This is not the usual “accuracy increases with more context” question. The object is an **instance-level reversal**:

```text
wrong -> correct   expected learning
correct -> correct expected stability
correct -> wrong   evidence-induced forgetting / reversal
```

## Why this is interesting

More correct evidence should weakly increase support for the same true answer in an ideal evidence integrator. A substantial `correct -> wrong` transition rate would show that inference is not monotone even on naturally ordered, answer-preserving evidence.

That is much more concrete than a generic “longer context can hurt” statement.

## Existing resources

The strongest feature of this candidate is cost:

- the response dataset already contains model responses across clue states;
- the progressive question dataset supplies answer keys and clue structure;
- G0 can first be performed by **offline trajectory analysis with no new model inference at all**.

## Critical caveat discovered in audit

CAIMIRA's human response processing imposes/backfills monotonic correctness for some progressive records. Therefore:

> **Do not claim “humans are monotone but LLMs are not” from those processed human rows.**

The first claim should be AI-only: does natural evidence create substantial correct-to-wrong reversal?

A human comparison is only legitimate if raw timestamped Protobowl behavior can be reconstructed without monotonic backfilling.

## Cheapest decisive experiment

1. Join released agent responses to question/clue order.
2. For each `model × original question`, construct the correctness sequence over clue count.
3. Measure:
   - first-correct clue;
   - number and rate of `1 -> 0` transitions after first correctness;
   - probability of later recovery;
   - answer identity before and after reversal.
4. Freeze a minimum reversal-density bar before doing explanatory analysis.

The first result should be a simple transition matrix / survival curve, not a classifier.

## Kill line

Kill if clean `correct -> wrong` events are very sparse after removing duplicated/missing/non-comparable trajectories, or if almost all events are attributable to trivial answer-normalization/parsing issues.

## Collision audit

There is broad literature showing that more context or more retrieved evidence can sometimes hurt LLM performance. However, current searches did not find an exact study of **instance-level correct-to-wrong transitions over naturally progressive Quiz Bowl clues** using this released trajectory resource.

The distinction matters: context-length degradation mixes distraction, truncation, and task changes. Here the later clue is true, answer-preserving, and part of the original human-authored question.

## Positive-result headline

> **A model can know the right answer, receive more true evidence for the same question, and become wrong.**

## Method / mechanism opening

- answer-state persistence / hysteresis;
- evidence weighting by clue position or specificity;
- intervention on reversal points;
- confidence-aware stopping (“answer when you know, do not overwrite without enough contradictory evidence”);
- evidence aggregation training.

## Resource gate

```text
Paid API requirement for G0: none
New annotation requirement for G0: none
Local compute: near-zero for released-response G0
Released-artifact-only G0: yes
```

**Status:** `TOP_POOL`

# 5. DEEP_AUDIT 1 — Does Learning a Capability Make It Quantization-Fragile?

## Seed / external anchor

Ouyang et al., ACL 2025, **“Low-Bit Quantization Favors Undertrained LLMs.”**

- ACL: https://aclanthology.org/2025.acl-long.1555/
- arXiv: https://arxiv.org/abs/2411.17691
- released checkpoint collection: https://huggingface.co/Xu-Ouyang

The work evaluates 1500+ quantized checkpoints and establishes a counterintuitive global fact: as models are trained more fully, low-bit post-training quantization can hurt them more.

## Important collision discovered this round

This lane became much more crowded in 2025–2026.

- **Training Dynamics Impact Post-Training Quantization Robustness** traces quantization error across open training trajectories up to 32B / 15T tokens and links changes strongly to training dynamics such as learning-rate decay.
- **When Flat Minima Fail: Characterizing INT4 Quantization Collapse After FP32 Convergence** traces all 154 Pythia-160M checkpoints and reports a post-convergence INT4 divergence phase.

Therefore the generic question

> “when during training does quantization become fragile?”

is **already collided** and must not be pursued.

## Surviving one-step question

The still-interesting question is capability-specific:

> **When a new downstream capability is acquired during pretraining, does that capability become especially low-bit fragile at or after its acquisition?**

Equivalent framing:

> **Does learning a capability make it precision-dependent?**

This is an interaction between two independently meaningful axes:

```text
capability acquisition time × quantization fragility onset
```

not another global loss-vs-quantization curve.

## Existing resources

- released quantized checkpoints from the ACL 2025 work;
- Pythia / other dense open checkpoints;
- automatic benchmarks with gold answers;
- existing capability-emergence literature can pre-specify tasks instead of task fishing.

## Cheapest decisive experiment

Do **not** start with hundreds of tasks.

Freeze 3–4 automatic tasks with demonstrably different acquisition curves in one checkpoint family. For each:

1. estimate full-precision capability curve over training;
2. estimate fixed-bit quantized capability curve;
3. define acquisition onset and fragility onset using frozen thresholds;
4. ask whether later-acquired capabilities systematically show later/sharper quantization fragility aligned to their own acquisition rather than simply global checkpoint age.

The useful signature is not “task A degrades more than task B.” It is **within-task temporal coupling between learning and precision sensitivity**.

## Kill line

Kill if:

- chosen open model never reaches a meaningful baseline on the tasks;
- all tasks simply track a single global quantization-loss curve;
- onset relation disappears after one locked task set;
- a convincing result requires searching many tasks / thresholds for alignment.

## Positive-result headline

> **Capabilities become low-bit fragile as they are learned, linking capability acquisition to precision dependence.**

## Method opening

- capability-aware mixed precision;
- checkpoint-specific precision budgets;
- quantization-aware curricula near acquisition periods;
- selectively protect representations supporting newly acquired skills.

## Resource gate

```text
Paid API requirement for G0: none
New annotation requirement for G0: none
Local compute: moderate; checkpoint inference and storage dominate
Released-artifact-only G0: potentially yes
```

**Status:** `DEEP_AUDIT / HIGH`

Reason not promoted to TOP yet: nearby 2026 training-dynamics work is moving fast, and meaningful downstream capability acquisition must exist in the released model family without task fishing.

# 6. DEEP_AUDIT 2 — When Does a Model Know a Number Before It Can Say What It Knows?

## Seed

Yuchi, Du, Eisner, EACL 2026, **“LLMs Know More About Numbers than They Can Say.”**

The paper reports a sharp representation–behavior gap: hidden states linearly encode numerical magnitude strongly enough for high pair-ranking accuracy, while explicit mixed-notation numerical ranking remains much weaker.

The paper also explicitly leaves causal use of the internal numerical representation unresolved.

## Natural one-step question A: developmental timing

> **During pretraining, does a robust numerical-magnitude representation emerge before the model can reliably verbalize/carry out the corresponding mixed-notation comparison?**

This would turn the final-model dissociation into a developmental ordering question.

## Natural one-step question B: causal use

> **On items the model answers incorrectly, is the correct magnitude ordering already present internally but failing to control the output?**

B is scientifically sharper but intervention-heavy; A is cheaper and more advisor-like.

## Collision risk

Recent work already studies numerical geometry across model families and training, and training-dynamics papers have traced arithmetic / Greater-Than circuits over Pythia checkpoints. Therefore this candidate is not yet clean enough to promote.

## Resource gate

Open weights and automatic numeric labels make the cost excellent; the main risk is **scientific collision / final-model capability floor**, not money.

**Status:** `DEEP_AUDIT`

# 7. WATCH — Does Task Knowledge Emerge Before Answer-Interface Binding?

## Seeds

Two recent results meet naturally:

1. GEM² 2025 / related checkpoint work reports intermediate models that can identify the correct answer text while failing to emit the required A/B/C/D symbol.
2. 2026 work on when models “decide” vs “bind” reports a two-stage computation in final LLMs: content winner information appears before the final output-symbol binding.

## Candidate question

> **Across pretraining, does content-space decision competence emerge systematically before arbitrary answer-symbol binding, so that part of benchmark “emergence” is really interface acquisition rather than knowledge acquisition?**

## Why only WATCH

- automatic, cheap, open-checkpoint compatible;
- very clean axis × object construction;
- but a positive result is fairly plausible/expected once the two seed results are known;
- symbol binding is already an active literature.

**Status:** `WATCH / HIGH`

# 8. WATCH — Do Models Satisfy Every Constraint Separately but Fail Their Composition?

## Seed

ACL 2026 **MulDimIF**:
https://aclanthology.org/2026.findings-acl.99/

It releases 9,106 code-verifiable multi-constraint instructions and shows a large performance decline from easier to more complex constraint settings.

## Candidate question

> **For an instruction whose atomic constraints are all individually satisfiable by the same model, how often does the model still fail their joint composition?**

This is the instruction-following analogue of local-vs-global NA.

## Why not TOP

The space is already crowded by FollowBench, InFoBench, fine-grained verification, compositional training, RECAST/RLVC, MulDimIF, and very recent constraint-scaling work. The exact conditional dissociation may still be measurable, but the headline is less novel than the NA version.

## Resource gate

Excellent: released code-verifiable labels, open models, no annotation.

**Status:** `WATCH / CROWDED`

# 9. WATCH — Are Citation-Bearing Legal Summary Sentences a Hidden Factuality Failure Mode?

## Seed

Heddaya et al., Findings NAACL 2025, **CaseSumm**:
https://aclanthology.org/2025.findings-naacl.102/

Resources:
https://huggingface.co/datasets/ChicagoHAI/CaseSumm

The paper releases 25.6K SCOTUS opinion–syllabus pairs and finds a strong metric/evaluation mismatch: fine-tuned Mistral performs well on automatic metrics but human experts find hallucinations. Error analysis includes precedent-citation errors and case-fact misrepresentations.

## Possible one-step

> **Do automatic metrics remain high specifically when summaries hallucinate or misattribute legal precedents, making citation-bearing claims a systematic blind spot?**

A stronger version would programmatically verify cited precedents against the source opinion / opinion citation graph.

## Resource problem

The core “factual error” label is exactly where expert human judgment mattered in the seed paper. Unless citation errors can be converted into a narrow deterministic verification task, this violates our new annotation-cost gate.

**Status:** `WATCH / RESOURCE-RISK`

# 10. WATCH — Why Do Dependent Patent Claims Degrade After a Good Independent Claim?

## Seed

Jiang et al., Findings NAACL 2025, **“Can Large Language Models Generate High-quality Patent Claims?”**
https://aclanthology.org/2025.findings-naacl.70/

The paper reports that LLMs can generate relatively strong first independent claims but quality falls substantially for subsequent dependent claims.

## Natural next question

> **Is the degradation driven by dependency depth / inherited constraints, such that errors propagate along the legal claim dependency structure?**

This is more concrete than “patent generation is hard.”

## Resource problem

The meaningful quality dimensions—feature coverage, clarity, technical coherence, legal robustness—were evaluated with patent experts. Automatic structural checks alone may not identify the scientifically interesting failure.

Unless the released dataset supports an exact low-ontology dependency-consistency measurement, do not promote.

**Status:** `WATCH / RESOURCE-RISK`

One notable anomaly is that models can sometimes answer their own invalid questions, indicating that generation validity and answer knowledge are not the same thing.

## Candidate question

## Why only WATCH

# 12. COLLISION_RISK — Why Do Synthetic Participants Inflate Treatment Effects?

## Seed phenomenon

Recent 2025–2026 large-scale social-science replications with LLM synthetic participants report systematic overestimation of experimental treatment effects, including false positives on experiments that were null in humans.

This is a real and important anomaly.

## Initial one-step considered

> **Is effect inflation caused by synthetic participants compressing real human response heterogeneity / variance?**

## Why downgraded

Current work is already directly reporting reduced synthetic-response variance / homogeneity and connecting it to biased effect estimation. The exact explanatory direction is therefore becoming crowded.

Do not promote by merely renaming “variance compression.” Search for another unexplained dissociation if revisiting this lane.

**Status:** `COLLISION_RISK`

# Round-02 conclusion

The strongest lesson from this round is that **resource feasibility and scientific cleanliness are aligned more often than they conflict**.

The two best current candidates do not need GPT-5, a custom annotation campaign, or large training:

1. NA local-vs-global rejection uses existing gold MCQ structure and open inference.
2. Progressive-clue reversal may be testable entirely from already released response trajectories.

Both have the desired shape:

```text
published / naturally occurring phenomenon
-> one adjacent, sharper question
-> one clean behavioral contrast
-> automatic measurement
-> hard kill if the critical dissociation is absent
-> clear mechanism/method opening if positive
```

That is a substantially better profile than candidates whose first step is to invent an ontology, hire annotators, or spend money on large closed-model sweeps.
