# Phenomenon Mining — Round 02 (2026-08-23)

## Purpose

Round 01 deliberately generated broad phenomenon leads. Round 02 immediately stress-tests them against the newest 2026 literature so we do not repeat the repository's old mistake of promoting a nice-sounding adjacent gap that is already occupied.

---

# 1. P2 is substantially collided: generic repertoire narrowing is already reported

Round 01 P2 asked whether RL can improve reward while shrinking the successful behavioral repertoire.

A very recent paper, **Internalizing Agency from Reflective Experience (LEAFE, arXiv:2603.16843)**, already states essentially this phenomenon for outcome-driven agentic post-training:

- outcome-driven methods can cause **distribution sharpening**;
- the policy becomes better at reproducing a narrow set of already-successful behaviors;
- feedback-grounded agency does not expand correspondingly;
- Pass@k/capacity to explore alternatives suffers relative to their reflective-experience method.

URL: https://arxiv.org/abs/2603.16843

### Decision

`P2 -> COLLIDED AS A BROAD HEADLINE`

Do not register "RL narrows the behavioral repertoire" as our topic.

What remains potentially open is much more specific:

> **During peak-to-final degradation, which concrete behavioral capability collapses first / most sharply?**

This keeps P1 alive but makes the bar stricter.

# 2. P3 is now clearly a crowded method/problem space

Round 01 P3 asked what ordinary agentic RL fails to learn from environment feedback.

The collision search finds multiple 2026 works attacking essentially this gap from different directions:

1. **SOAR — Supervision from Observation for Agentic Reinforcement Learning**, ACL 2026
   - directly argues observations are underused;
   - adds supervision derived from observation tokens.
   - https://aclanthology.org/2026.acl-long.1624/

2. **LEAFE — Internalizing Agency from Reflective Experience**, 2026
   - explicitly targets feedback-grounded recovery agency and distribution sharpening.
   - https://arxiv.org/abs/2603.16843

3. **HERO — Hindsight-Enhanced Reflection from Environment Observations for Agentic Self-Distillation**, 2026
   - converts environment observations into turn-level diagnoses and improves success / unnecessary-turn behavior.
   - https://arxiv.org/abs/2606.11559

4. **EFCA — Learning from Environmental Feedback: Credit Assignment across Multiple Timescales for Agentic RL**, Aug 2026
   - uses immediate environmental feedback plus history-based process signals.
   - https://arxiv.org/abs/2608.08255

5. **Agentic Distillation**, ICLR 2026 submission
   - directly optimizes feedback-token-derived knowledge in addition to internal reasoning tokens.
   - https://openreview.net/pdf?id=zyp9QT5Gf1

### Decision

`P3 -> COLLIDED AS A BROAD PROBLEM`

The question "does agentic RL underuse feedback?" is **not ours anymore**.

Only keep a future subproblem if we first observe a concrete deficit that none of these papers already isolates.

Examples of a sufficiently specific future phenomenon:

- failure feedback is used within the same episode but systematically fails to transfer across episodes;
- agents learn to avoid repeated invalid calls but not to anticipate deterministic consequences before acting;
- recovery capability peaks mid-training and then disappears despite final success staying high;
- environmental rules are retained only when re-observed, with a sharp context-removal boundary.

But we are not allowed to assume any of these occur.

# 3. P1 remains the strongest lead, but the target must be narrower

## Broad fact already occupied

ActFocus already reports **peak-to-final degradation** under vanilla GRPO in several agentic environments.

So our contribution cannot be:

> GRPO sometimes degrades late.

## Remaining open observational object

The more specific phenomenon-mining target is:

> **What behavior is lost between the peak checkpoint and the final degraded checkpoint?**

This is still not answered by saying "entropy collapses" or "action tokens receive poor credit." Those are mechanisms/aggregates.

The output of P1 must be a concrete behavioral statement, such as:

```text
recovery after one failed action collapses from X to Y
while first-try competence stays roughly constant
```

or

```text
state-conditional route switching disappears
while the dominant route gets more reliable
```

or

```text
invalid-action avoidance improves
but exploratory branch diversity collapses before aggregate reward falls
```

The exact statement must come from traces.

### Revised status

`P1 -> REPLICATE_NOW / TOP PRIORITY`

# 4. New lead P9 — Training-side improvement can fail to become inference-side improvement

**Status:** `OBSERVED / PROBABLY COLLIDED FOR METHOD, USE AS PHENOMENON SHAPE`

## Existing observation

**The Mirage of Optimizing Training Policies: Monotonic Inference Policies as the Real Objective for LLM RL** (arXiv:2606.29526) reports that separate training and inference engines can assign inconsistent probabilities to identical trajectories even with synchronized parameters. An update that improves the training-side policy need not improve the actual inference-side policy.

URL: https://arxiv.org/abs/2606.29526

## Why this matters to mining

This is an unusually clean example of a systems-level phenomenon that directly changes learning behavior:

```text
same nominal weights
same trajectory
training engine probability != rollout/inference engine probability
```

It is a reminder to inspect RL phenomena at the **deployed sampler**, not only trainer statistics.

## Why not register it

The paper already owns both diagnosis and method (MIPI/MIPU). There is no obvious unoccupied headline.

## Reusable mining implication

When analyzing P1, record both:

- trainer-side policy quantities;
- rollout-engine behavior/probabilities where feasible.

Do not accidentally call a trainer-only change a behavioral phase transition.

# 5. New lead P10 — Recovery behavior may be the most valuable trace primitive

**Status:** `WATCH / PROMISING OBSERVABLE`

Several recent papers independently emphasize recovery:

- LEAFE: feedback-grounded recovery agency;
- HERO: local diagnoses from next observations;
- Agentic Critical Training: qualitative examples where one model loops on a failed action while another diagnoses and recovers;
- VLCP on robotics: failed grasps form a measurable recoverable population.

This means **recovery is real and important**, but also increasingly crowded as a method target.

The potential opening is not "recovery matters." It is a more basic training-dynamics phenomenon:

> **How does recovery competence itself evolve across checkpoints?**

Possible mechanical definition in symbolic agent environments:

```text
inject one known recoverable error at matched state
-> give standard environment feedback
-> measure probability of returning to any successful path within K steps
```

This is attractive because:

- the error can be environment-defined;
- no LLM judge is needed;
- the same state can be tested across checkpoints;
- it yields a direct curve across RL training;
- it can expose non-monotonic collapse/recovery.

But this is still only an **experimental primitive** until a surprising curve is actually observed.

### Status

`P10 -> CHEAP_OBSERVATION_PROBE`, not a topic.

# 7. Practical next experiment is now sharper

Instead of training a giant agent system and inspecting everything, the first useful local run should answer exactly two observation questions:

### O1 — Does vanilla GRPO reproduce peak-to-final degradation here?

If no: stop this branch.

### O2 — Does recovery competence follow the aggregate reward curve?

At dense checkpoints, from matched recoverable states:

```text
checkpoint -> P(recover within K steps)
checkpoint -> P(repeat failed action)
checkpoint -> P(switch to a valid alternative)
checkpoint -> steps-to-recovery
```

This is deliberately not a mechanism test.

The most exciting possible outcome would be something like:

> aggregate success remains high / peaks, but recovery competence collapses sharply later.

That would create a real object worth explaining and a direct method target.

If recovery simply tracks success smoothly, move on. No rescue.
