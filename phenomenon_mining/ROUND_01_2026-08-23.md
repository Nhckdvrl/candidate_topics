# Phenomenon Mining — Round 01 (2026-08-23)

## Objective

Search for **already-visible phenomena** in research-room-aligned areas and identify which ones deserve immediate reproduction/mining. This round intentionally avoids inventing a final mechanism hypothesis.

The standard is:

> Can we point to an existing curve/trace/checkpoint sequence and say: **that behavior is real, large, weird, and worth understanding**?

If not, it does not enter the shortlist.

---

# 1. Lead P1 — What disappears after the peak in agentic RL?

**Status:** `REPLICATE_NOW`

## Existing observation

ActFocus reports that vanilla PPO/GRPO agentic training can show substantial **peak-to-final degradation**, and that action-focused reweighting improves training stability. This is already a checkpoint-level phenomenon, not our conjecture.

The paper's headline explanation is token-level credit misallocation. We should **not** duplicate that claim.

## Phenomenon-first question

> During a run whose aggregate success peaks and then falls, **what exactly disappears from the agent's behavior?**

Possible directly observable categories, to be discovered rather than assumed:

- exploration disappears;
- first-action diversity collapses;
- recovery after a bad action disappears;
- tool-use becomes repetitive;
- the agent keeps successful action templates but loses state-conditional switching;
- reasoning length changes without useful behavioral change;
- one task family improves while another collapses;
- the same prompt moves from multi-strategy to single-strategy behavior.

The important point is that these are **trace labels we can define mechanically where possible**, not a precommitted mechanism story.

## Why this lead is strong

1. The aggregate phenomenon already exists in a recent open agentic-RL paper.
2. The environments are accessible: Sokoban, FrozenLake, Sudoku, WebShop-style agent setups.
3. Multiple checkpoints can be saved cheaply on local training.
4. The object is behavior/trace, not a hidden state.
5. A strong result has a clear method opening: preserve the disappearing behavior, trigger rollback, adaptive regularization, or state-dependent credit allocation.
6. Our local 4-GPU node is sufficient for Qwen2.5/Qwen3 0.5B–3B agentic RL replication-class runs.

## First replication target

Do not start with a mechanism probe.

Run one baseline GRPO agent setup with dense checkpointing and record:

```text
checkpoint
success rate
per-state first-action distribution
unique action sequences
retry / backtrack count
recovery-after-first-error rate
invalid-action rate
trajectory length
reasoning-token count
action-token count
policy entropy on action positions
```

Then inspect peak vs final **without training a classifier or defining a causal explanation**.

### P0 gate

Proceed only if:

- final success falls materially below peak on >=2 seeds or >=2 environments; and
- at least one behavior-level quantity shifts visibly with the degradation; and
- representative trajectories make the shift human-inspectable.

If peak-to-final degradation does not reproduce, kill this local lead immediately rather than tuning until it appears.

## Paper-shape if alive

Potential headline shape:

> Agentic RL does not merely overfit late in training; it undergoes a reproducible behavioral collapse in which **[observed capability]** disappears while **[other capability]** remains.

Only after seeing the missing behavior should we ask why.

# 2. Lead P2 — Does RL improve reward while reducing behavioral repertoire?

**Status:** `REPLICATE_NOW`, tightly coupled to P1

## Existing observation

Recent RL-mechanism work reports that RL can reshape the distribution of reasoning patterns while individual pattern success rates remain relatively stable. Entropy-collapse work independently reports increasingly imbalanced entropy flow during training.

That makes one observation family worth mining:

> **Does task reward continue to improve while the set of distinct successful behaviors shrinks?**

This is not the already-done statement "entropy goes down." The target is **successful behavioral repertoire**, measured in action/strategy space.

## Why it may be exciting

If real and large, it changes the meaning of an RL improvement curve:

```text
higher success
!=
strictly more capability
```

A policy could become better on the metric by selecting a narrower set of successful strategies while losing alternatives needed for robustness, transfer, or recovery.

## Direct observables

Prefer environment-defined quantities over LLM judges:

- number/effective number of successful action sequences;
- first-decision support size;
- state-conditioned action entropy;
- path diversity in symbolic environments;
- number of distinct successful solution families for Sudoku/Sokoban where canonicalization is possible;
- recovery-route diversity after injected errors.

## Main collision risk

Generic entropy collapse and pattern selection are already occupied. Promotion requires a **behaviorally meaningful loss of successful alternatives** tied to robustness/recovery, not just lower token entropy.

## Kill line

If action/solution repertoire tracks reward monotonically or the effect exists only under arbitrary clustering metrics, reject.

# 3. Lead P3 — What does ordinary agentic RL fail to learn from environment feedback?

**Status:** `OBSERVED_TENSION / DO_NOT_PROMOTE_YET`

## Existing observation

Standard multi-turn RL commonly keeps tool/environment observations in context while applying policy loss to assistant-generated tokens. SOAR explicitly adds supervision derived from observation tokens and reports improvements; Agentic Distillation similarly introduces learning from feedback tokens.

Therefore this is a **real training-structure tension**, but not yet a direct phenomenon we own.

## Phenomenon mining target

Do not ask yet:

> Does RL internalize feedback knowledge?

That repeats the old hypothesis-first mistake.

Instead compare standard-RL checkpoints behaviorally on a set of **feedback-conditioned micro-events**:

```text
action -> deterministic environment response -> next decision
```

Mine what improves and what stubbornly does not:

- anticipating deterministic tool consequences;
- avoiding immediately repeated failed calls;
- remembering a discovered environment rule later in the episode;
- transferring a discovered rule to a new episode without the tool response present;
- distinguishing transient feedback from persistent environment facts.

The first goal is an empirical map:

```text
standard RL learns A/B/C
but repeatedly fails on D
```

Only D, if strong and replicated, becomes a project.

## Why this is promising

It sits exactly at the intersection of:

- agentic RL;
- learning from interaction;
- reasoning/behavior traces;
- method opening via feedback-aware objectives;
- local trainability.

But **no numbered topic until an actual deficit is observed**.

# 4. Lead P4 — Strategy phase transitions during reasoning RL

**Status:** `WATCH / MINE RELEASED TRACES`

## Existing observation

ICLR 2026 work reports RL-driven redistribution among reasoning patterns and sparse critical-token optimization. Other recent papers show non-monotonic performance across training or prompting settings.

## Phenomenon-first target

Mine dense checkpoints for **discrete behavioral transitions**, e.g.:

- sudden onset of verification;
- sudden disappearance of enumeration;
- backtracking appears for a window and then vanishes;
- answer length changes smoothly but strategy usage jumps;
- a new successful strategy appears before aggregate accuracy moves;
- aggregate accuracy barely changes while dominant solution type flips.

## Why this is better than another mechanism hypothesis

A true phase transition would already be a strong scientific object. It can later motivate:

- curriculum timing;
- checkpoint selection;
- strategy-preserving RL;
- targeted sampling around transition windows;
- mechanistic analysis of a **known transition**, not a guessed one.

## Main risk

Trace taxonomy can become LLM-judge-heavy. Prefer environments with mechanically identifiable strategies or carefully defined local events.

# 5. Lead P5 — VLA action-chunk stale-control window

**Status:** `REPLICATE_NOW` if embodied lane is active

## Existing observation

A2C2 reports that action chunking harms reactivity under inference delay and long execution horizons, and per-step correction substantially improves dynamic-task success. This directly establishes a stale-control problem.

## Phenomenon-first question

> Within an action chunk, **when does the policy's planned action become behaviorally stale relative to the newest observation?**

Do not ask for a hidden representation. Measure the control mismatch across chunk position.

Candidate direct curves:

```text
chunk index -> action disagreement after fresh observation
chunk index -> counterfactual correction magnitude
chunk index -> task-space error growth
chunk index -> recovery probability if replanning occurs now
```

## Why this could matter

If there is a sharply structured **staleness horizon** rather than smooth generic degradation, it exposes a direct adaptive-chunking / event-triggered replanning lever.

## Collision constraint

A2C2 already establishes that correcting chunks helps. A project must discover a stronger regularity than "later actions are worse".

Potentially interesting outcomes include:

- staleness appears immediately after contact events regardless of chunk index;
- certain action dimensions become stale much earlier than others;
- successful policies retain open-loop validity until a task-state transition, then fail abruptly;
- fresh observation changes policy intent long before the executed chunk reflects it.

These are observations to mine, not hypotheses to register.

# 6. Lead P6 — Recoverable vs terminal robot-policy failures

**Status:** `WATCH`

## Existing observation

Recent closed-loop robot systems report sizable within-episode recovery populations; VLCP reports a 27.3% recovery rate on failed grasps in its setup, while broader VLA work repeatedly emphasizes policy-induced recovery states.

## Mining target

Construct a **failure-state atlas** from open simulation rollouts:

```text
failure precursor
immediate next observation
base policy continuation
replan / correction outcome
recovery success
```

The question at this stage is only:

> Are failures naturally divided into a small number of strongly different recovery regimes?

No latent "self-awareness" or confidence story.

## Promotion bar

Need a large, stable behavioral partition with a clean intervention opening. If the taxonomy needs manual semantic labeling or every task has unrelated failure modes, reject.

# 7. Lead P7 — Deployment semantics can dominate VLA checkpoint identity

**Status:** `OBSERVED / LOWER LAB FIT`

## Existing observation

Recent work shows that identical VLA weights can produce dramatically different executable policies under plausible action unnormalization metadata mismatch, collapsing replay success.

## Why interesting

This is unusually concrete and large. It suggests "the model checkpoint" is not the full policy object.

## Why not top priority

The direct headline is already largely established and the extension space may become deployment tooling rather than the learning/mechanism research style we want.

Keep as a source of broader questions about executable policy invariances, but do not spend the first mining budget here.

# 8. Lead P8 — Non-monotonic SFT/RL generalization trajectories

**Status:** `WATCH / CROWDED`

## Existing observation

Multiple 2025–2026 studies report non-monotonic OOD trajectories during reasoning SFT/post-training: degradation followed by recovery in some settings, improvement followed by decline in others, and early SFT checkpoints sometimes initialize downstream RL better than later checkpoints.

## Why not immediately promote

"More SFT hurts OOD" and "there is an optimal checkpoint" are no longer surprising enough.

Only keep if mining reveals a stronger direct phenomenon such as:

- a specific capability disappears and then reappears;
- recovery occurs without re-exposure to the lost domain;
- different capabilities recover in a fixed order;
- RL restores one behavioral mode while leaving another permanently lost.

Again: observe first, explain later.

# 10. Immediate work order

The next mining effort should **not create Topic 20 yet**.

Do this order:

1. reproduce an open agentic-RL baseline with dense checkpoints;
2. verify whether peak-to-final degradation is present without tuning for it;
3. dump and compare peak/final traces;
4. mechanically quantify action diversity, recovery, retries, invalid calls and state-conditional switching;
5. in parallel, inspect existing public RL checkpoint traces for abrupt strategy transitions;
6. only if one visible behavior repeatedly changes, freeze that object and run an independent confirmation;
7. then decide whether it deserves a numbered candidate.

The central discipline is:

> **We are not trying to make a hypothesis work. We are trying to discover which large behavior is already happening.**
