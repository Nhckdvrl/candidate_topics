# Phenomenon Mining — Round 03 (2026-08-23)

## Why another round immediately

The first two rounds still left a danger: agentic RL is moving so quickly that even a trace-level phenomenon can already be occupied. This round searches specifically for collapse/recovery/feedback papers to see what remains genuinely open.

---

# 1. Important collision: RAGEN-2 already owns a hidden reasoning-collapse phenomenon

**RAGEN-2: Reasoning Collapse in Agentic RL** (ICML 2026 Oral, arXiv:2604.06268) reports a particularly strong phenomenon:

> entropy can remain stable while reasoning becomes input-agnostic and collapses into generic templates.

They call this **template collapse**, diagnose it using cross-input mutual information, explain it through low reward-variance / SNR, and propose SNR-aware filtering.

URLs:

- https://arxiv.org/abs/2604.06268
- https://ragen-ai.github.io/

This directly occupies several naive versions of our Round-01 P1/P4 ideas:

- "reasoning collapses late in agentic RL";
- "entropy misses behavioral collapse";
- "strategy diversity disappears";
- "reasoning becomes templated."

### Consequence

Do **not** use any of these as a new headline.

But RAGEN-2 also sharpens our search target: after subtracting template collapse, what **environment-facing competence** degrades?

---

# 2. Recovery itself is also an increasingly explicit research object

The collision search found several direct recovery-focused works:

- LEAFE: feedback-grounded recovery agency from reflective experience;
- HERO: turn-level diagnoses from observations;
- TALE: tool-agent learning from execution errors;
- structured reflection work: failed-call diagnosis and corrected tool calls;
- agentic-search behavior studies: Error Recovery listed as a beneficial reasoning behavior;
- ICLR 2026 search-agent work explicitly defines and measures recovery competence using an Evidence Recovery Function;
- Agentic Critical Training presents loops vs recovery as a core qualitative difference.

Therefore:

> "agents are bad at recovery" or "training recovery improves agents"

is **not** a sufficiently novel research question.

# 3. What remains plausibly open: the *training trajectory* of recovery competence

Despite the crowding, the literature found so far mostly compares:

```text
method A vs method B
final model A vs final model B
recovery-trained vs baseline
```

The cleaner unresolved phenomenon is developmental:

> **As ordinary agentic RL proceeds, does recovery competence improve monotonically with task success, or can it peak, collapse, or decouple from first-try competence?**

This is not yet promoted as a topic. It is a **phenomenon probe**.

## Why this object survives the archive lessons

### Directly measurable

In symbolic/tool environments, define a state with a known recoverable error and deterministic feedback.

For checkpoint `c`:

```text
R(c) = P(return to a successful path within K turns | matched recoverable failure state)
```

Also measure:

```text
repeat_failed_action(c)
switch_to_valid_alternative(c)
steps_to_recovery(c)
first_try_success(c)
```

No hidden representation. No LLM judge required for environments with programmatic validity.

### One clean contrast

Same failure state, same feedback, different training checkpoint.

### Meaningful regime

Use an agent that already has non-trivial success and real multi-turn interaction.

### Excitement test

A genuinely non-monotonic result would be strong:

> **RL keeps making the agent better at avoiding easy mistakes while making it worse at recovering once it leaves the successful trajectory.**

or:

> **The final higher-reward policy has less recovery competence than an earlier checkpoint.**

That would immediately motivate checkpoint selection, recovery-preserving objectives, targeted replay, or training-time recovery audits.

Again: these are examples of what would be exciting, **not assumed outcomes**.

### Current status

`RECOVERY_TRAJECTORY -> TOP PHENOMENON_PROBE`

# 4. Strong warning from SFT->RL rank inversion

**SFT Overtraining Predicts Rank Inversion via Entropy Collapse Under RLVR** (arXiv:2606.18487) reports a direct counterexample to the heuristic "best SFT pass@1 is best RL initialization": deeper SFT can raise pre-RL pass@1 while producing substantially worse peak GRPO pass@10 in one model family.

URL: https://arxiv.org/abs/2606.18487

This exact topic is already occupied, but it reinforces a useful phenomenon-mining rule:

> **Do not treat aggregate competence before training as evidence of healthy learning capacity.**

For our agent runs, preserve early checkpoints and separately track:

- first-try competence;
- recovery competence;
- input dependence;
- successful-path repertoire;
- group reward variance / learnability.

Any pair that moves in opposite directions is more scientifically interesting than one more aggregate success curve.

# 5. Another major collision: capability-boundary / diversity collapse in RLVR is crowded

2026 work now includes:

- RL-PLUS: "capability boundary collapse" and Pass@k narrowing;
- DSDR: loss of path-level diversity despite local entropy;
- RAGEN-2: template collapse despite stable entropy;
- LEAFE: distribution sharpening around narrow successful behaviors;
- multiple token-level entropy-collapse methods.

Therefore the entire broad space

> "RL improves Pass@1 but shrinks diversity / exploration"

is no longer a good standalone topic.

This is important because it kills another tempting old-style idea **before we code it**.

# 6. VLA lane survives better than generic agentic-collapse mining

The VLA action-chunk / closed-loop reactivity literature is active, but the direct observational space still seems less saturated than agentic RL collapse.

The currently strongest phenomenon-mining object remains:

> **the shape of control staleness after task-state transitions/contact events within an action chunk.**

A2C2 already shows that correcting chunks helps. It does **not automatically imply** that staleness is a smooth function of chunk position.

The useful mining target is to inspect whether mismatch is event-driven:

```text
pre-contact          -> old chunk remains valid
contact transition   -> fresh-observation action jumps sharply
post-contact         -> stale chunk accumulates task-space error
```

If a sharp event-conditioned discontinuity exists across tasks/policies, that is a more interesting phenomenon than generic delay degradation and naturally motivates event-triggered replanning/adaptive chunk termination.

### Status

`VLA_EVENT_STALENESS -> SECOND PHENOMENON_PROBE`

No topic registration until the curve is seen.

# 7. Broader training-dynamics lane: useful anomaly shapes, mostly occupied

This round also found several high-quality examples that help calibrate what a phenomenon-first paper looks like:

### Logical Phase Transitions (ACL 2026)

Reasoning remains stable then collapses abruptly beyond a critical logical depth.

This is an excellent **shape**: one simple x-axis, one direct behavioral y-axis, abrupt transition, obvious curriculum lever. But the specific problem is already done.

### SFT generalization loss -> RL restoration

Recent work reports that SFT can lose OOD capability and RL can conditionally restore it, with restoration failing outside a certain SFT-depth range.

Again, good phenomenon shape, but already occupied.

### OLMo-style post-training behavioral shifts

Public multi-stage checkpoints make it possible to ask when a behavior appears/disappears. However, the workspace must avoid generic "compare pretrained/SFT/DPO/RL" papers. A specific, surprising behavioral object is still required first.

# 8. Updated shortlist after three rounds

## Tier A — actually worth running a phenomenon probe

### A1. Checkpoint-wise recovery trajectory in ordinary agentic RL

Goal: see whether recovery competence decouples non-monotonically from aggregate/first-try success.

Why #1:

- direct programmatic observable;
- dense checkpoint axis;
- strong lab fit;
- local compute feasible;
- survives generic feedback/template/diversity collisions by asking a more specific developmental question;
- method opening is immediate if a collapse exists.

### A2. Event-conditioned stale-control transition inside VLA action chunks

Goal: see whether fresh-observation action disagreement jumps around contact/task-state transitions rather than merely growing smoothly with chunk position.

Why #2:

- direct policy/control observable;
- no semantic judge;
- meaningful robotics regime;
- natural adaptive-chunk/replan lever;
- less crowded than generic agentic-RL collapse.

## Tier B — continue source mining before any run

### B1. Mechanically identifiable strategy transitions in reasoning RL

Only if a task admits strategy labels without LLM judging.

### B2. Cross-stage capability loss/restoration in public checkpoint families

Only if an unusual behavior is already visible in existing results; do not blindly benchmark every stage.

## Killed as broad topics

- generic agentic RL underuses feedback;
- generic reasoning/template collapse;
- generic path-diversity / entropy collapse;
- generic reward-improves-but-repertoire-shrinks;
- generic recovery matters;
- generic training-vs-inference policy mismatch.

# 9. Concrete experimental primitive for A1

The first implementation should be deliberately small.

Choose one open symbolic agent environment with:

- deterministic/known action validity;
- recoverable failure states;
- open RL training code;
- non-trivial base success.

For a fixed evaluation bank of states:

1. identify a valid successful path;
2. inject exactly one recoverable wrong action;
3. expose the normal environment feedback;
4. from each saved checkpoint, sample N continuations;
5. programmatically score whether the agent returns to a successful path within K turns;
6. compare the recovery curve against ordinary success across training.

Primary plot:

```text
training step
  ├── normal success
  ├── first-try success
  └── recovery-after-injected-error
```

Secondary diagnostics only if the primary curves show a real separation:

```text
repeat same failed action
switch action
steps to recovery
input-dependence / MI
reward variance
```

Do not inspect layers. Do not train probes. Do not invent a mechanism until the behavioral plot earns it.

# 10. Round-03 conclusion

Three search rounds already killed several ideas that would previously have become numbered topics.

That is a success of the new process.

The strongest surviving direction is no longer a verbal hypothesis. It is a **specific plot we want to see**:

> `normal task success vs recovery-after-controlled-error across RL checkpoints`.

If those curves simply track each other, we lose almost nothing and move on.

If they sharply decouple or recovery collapses after a peak, then — and only then — we have something worth naming, explaining, and turning into a topic.
